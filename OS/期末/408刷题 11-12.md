### 一、单项选择题（第23-32题）

#### 23. 下列选项中，满足短任务优先且不会发生饥饿现象的调度算法是（ ）。
A. 先来先服务
B. 高响应比优先
C. 时间片轮转
D. 非抢占式短任务优先

**【答案】** B
**【解析】**
*   **A. 先来先服务 (FCFS)**：对短任务不利，不会饥饿。
*   **B. 高响应比优先 (HRRN)**：响应比 $R_p = \frac{\text{等待时间} + \text{要求服务时间}}{\text{要求服务时间}} = 1 + \frac{\text{等待时间}}{\text{要求服务时间}}$。
    *   当两个进程等待时间相同时，要求服务时间越短，响应比越高，体现了**短任务优先**。
    *   当一个长任务等待时间足够长时，其响应比也会逐渐升高，最终获得CPU，因此**不会发生饥饿**。
*   **C. 时间片轮转 (RR)**：对所有进程公平，不体现短任务优先（除非短任务能在极短时间内完成），不会饥饿。
*   **D. 非抢占式短任务优先 (SJF)**：典型的会导致长任务**饥饿**的算法。
故选B。

#### 25. 在支持多线程的系统中，进程P 创建的若干个线程不能共享的是（ ）。
A. 进程P 的代码段
B. 进程P 中打开的文件
C. 进程P 的全局变量
D. 进程P 中某线程的栈指针

**【答案】** D
**【解析】**
在多线程操作系统中，所有线程属于同一个进程，它们共享进程的资源，包括：
*   **代码段**（程序指令）
*   **数据段**（全局变量）
*   **打开的文件**、I/O设备等
但是，每个线程需要独立的执行流，因此必须拥有自己独立的：
*   **线程栈**（保存局部变量、函数参数、返回地址等）
*   **栈指针**
*   **程序计数器 (PC)**
*   **寄存器上下文**
因此，线程的栈指针是私有的，不能共享。故选D。

#### 26. 用户程序发出磁盘I/O 请求后，系统的正确处理流程是（ ）。
A. 用户程序→系统调用处理程序→中断处理程序→设备驱动程序
B. 用户程序→系统调用处理程序→设备驱动程序→中断处理程序
C. 用户程序→设备驱动程序→系统调用处理程序→中断处理程序
D. 用户程序→设备驱动程序→中断处理程序→系统调用处理程序

**【答案】** B
**【解析】**
I/O软件的层次结构通常如下（由上至下）：
1.  **用户层软件**：用户程序发出I/O请求。
2.  **系统调用处理程序**：用户通过系统调用进入内核。
3.  **设备独立性软件**：进行逻辑设备到物理设备的映射等通用处理。
4.  **设备驱动程序**：向硬件控制器发送具体的机器指令，启动设备。
5.  **中断处理程序**：设备完成I/O后发出中断，CPU响应中断进行后续处理。
因此，正确的流程是：用户程序 $\to$ 系统调用 $\to$ 设备驱动 $\to$ 硬件I/O $\to$ 中断处理。
故选B。

| P4 | 0, 0, 1 | 2, 0, 0 | |

此时的安全序列是（ ）。
A. P1, P2, P3, P4
B. P1, P3, P2, P4
C. P1, P4, P3, P2
D. 不存在

>[^2]带领完成题目

**【答案】** D
**【解析】**
使用银行家算法进行安全性检查：
1.  **初始可用资源 (Available)**：(0, 2, 1)。

    *   当前 Available = (2, 2, 2)。

#### 28. 在缺页处理过程中，操作系统执行的操作可能是（ ）。
I. 修改页表
II. 磁盘I/O
III. 分配页框

A. 仅I、II
B. 仅II
C. 仅III
D. I、II 和 III

**【答案】** D
**【解析】**
当发生缺页中断时，操作系统需要：
1.  **分配页框 (III)**：为即将调入的页面寻找一个空闲物理内存块。如果内存已满，还需执行页面置换算法。
2.  **磁盘I/O (II)**：启动磁盘驱动程序，将所需的页面从外存（磁盘）读取到内存中。
3.  **修改页表 (I)**：页面调入内存后，需要修改页表对应的表项，将有效位（存在位）置为1，并填入物理块号。
因此I、II、III均会发生。
故选D。

#### 29. 当系统发生抖动（thrashing）时，可以采取的有效措施是（ ）。
I. 撤销部分进程
II. 增加磁盘交换区的容量
III. 提高用户进程的优先级

A. 仅I
B. 仅II
C. 仅III
D. 仅I、II

**【答案】** A
**【解析】**
*   **抖动 (Thrashing)**：是指系统频繁地进行页面调度（换入换出），导致CPU利用率急剧下降的现象。根本原因是系统中运行的进程过多，导致每个进程分配到的物理页框不足以容纳其工作集。
*   **措施 I (撤销部分进程)**：暂停或撤销部分进程可以释放内存空间，增加每个剩余进程可用的物理页框数，使其满足工作集需求，是解决抖动的**最根本、最有效**措施。
*   **措施 II (增加交换区)**：抖动是内存不足引起的，增加磁盘交换区容量不能解决内存紧张和频繁I/O的问题。
*   **措施 III (提高优先级)**：无法解决内存资源短缺的问题。
故选A。

#### 30. 在虚拟内存管理中，地址变换机构将逻辑地址变为物理地址，形成该逻辑地址的阶段是（ ）。
A. 编辑
B. 编译
C. 链接
D. 装载

**【答案】** C
**【解析】**
本题题意稍显绕口，需注意审题：“形成**该逻辑地址**的阶段”。
*   **逻辑地址**（即相对地址或虚地址）是在**链接**阶段形成的。链接程序将编译产生的目标模块链接在一起，形成一个完整的可执行程序，此时程序内部使用的是统一的逻辑地址空间（从0开始或基址）。
*   **物理地址**：在分页存储管理中，物理地址是在**执行**阶段由硬件地址变换机构（MMU）动态生成的（即重定位）。
*   题目问的是“形成该**逻辑地址**”的阶段，因此是**链接**阶段。
故选C。

#### 31. 某文件占10 个磁盘块，现要把该文件磁盘块逐个读入主存缓冲区，并送用户区进行分析。假设一个缓冲区与一个磁盘块大小相同，把一个磁盘块读入缓冲区的时间为100μs，将缓冲区的数据传送到用户区的时间是50μs，CPU 对一块数据进行分析的时间为50μs。在单缓冲区和双缓冲区结构下，读入并分析完该文件的时间分别是（ ）。
A. 1500μs，1000μs
B. 1550μs，1100μs
C. 1550μs，1550μs
D. 2000μs，2000μs

>小g：[^3]知识点讲解
     带领完成题目：看懂讲解后代入公式即可
     
**【答案】** B
**【解析】**
设 $T = 100\mu s$ (磁盘$\to$缓冲区), $M = 50\mu s$ (缓冲区$\to$用户区), $C = 50\mu s$ (CPU分析)。共 $N=10$ 块。

1.  **单缓冲区**：
    *   由于缓冲区是共享资源，磁盘写入缓冲区时（T），用户不能从缓冲区读取（M）。
    *   处理一块数据的流程：读入(T) $\to$ 传送(M) $\to$ 分析(C)。
    *   但是“传送(M)”和“分析(C)”是串行的（数据必须先传过去才能分析），而“分析(C)”是CPU操作，可以与下一块的“读入(T)”并行。
    *   **处理一块的时间**：
        *   第一阶段：I/O (T) + 传送 (M)。此时CPU忙于传送，不可进行上一块的分析（假设单CPU且传送需CPU参与，或者仅指总线冲突，通常单缓冲公式为 $\max(T, C) + M$ 或 $T+M$ 若不能重叠）。
        *   标准流水线计算：
            *   **第一块**：$T + M + C = 100 + 50 + 50 = 200$。
            *   **后续块 (2~10)**：当CPU在分析第 $i$ 块（耗时C=50）时，磁盘可以读入第 $i+1$ 块（耗时T=100）。但必须等第 $i+1$ 块读满且缓冲区空闲。
            *   **约束**：下一块的读入(T)必须等当前块的传送(M)完成才能开始（因为只有单缓冲区）。
            *   因此，一块的处理周期 = $T + M = 100 + 50 = 150\mu s$。
            *   在此期间，CPU分析上一块的时间 $C=50$ 完全被 $T+M$ 覆盖。
    *   **总时间** = $N \times (T + M) + C$ (最后一块分析)？
        *   实际上：$10 \times (100+50) + 50$ (最后一块分析) = $1550$。
        *   或者：第一块 150(T+M) + 此时开始分析第一块(50)。第二块T+M开始...
        *   总耗时 = $10 \times 150 + 50 = 1550\mu s$。
        *(注：单缓冲常见公式为 $(N-1)*\max(T+M, C+T?) + \text{First} + \text{Last}$. 但对于单缓冲，T和M必定串行，关键是T能否和C并行。但在单缓冲中，只有缓冲区空了才能T。缓冲区数据传完(M)后才空。所以T必须在M之后。即 T, M 是串行的循环主体。Cycle = T+M = 150。C=50与下一块的T并行。由于 $C < T+M$，所以耗时由 T+M 决定。)*

2.  **双缓冲区**：
    *   可以实现：磁盘往缓冲区1读(T)，同时用户从缓冲区2传(M)并分析(C)。
    *   **处理一块的时间**：$\max(T, M+C)$。
        *   $T = 100$。
        *   $M + C = 50 + 50 = 100$。
        *   两者相等，完美流水线。
    *   **总时间**：
        *   第一块读入 $T=100$。
        *   之后 9 块每块 $100$（因为流水线瓶颈是100）。
        *   最后一块传送+分析 $M+C=100$。
        *   总时间 $\approx T + (N-1)\times 100 + (M+C)$。
        *   $100 + 9 \times 100 + 100 = 1100\mu s$。

结果：1550, 1100。
故选B。

#### 32. 有两个并发执行的进程P1 和P2，共享初值为1 的变量x。P1 对x 加1，P2 对x 减1。加1 和减1 操作的指令序列分别如下所示。
```
// 加1 操作 (P1)      // 减1 操作 (P2)
1. load R1, x        4. load R2, x
2. inc R1            5. dec R2
3. store x, R1       6. store x, R2
```
两个操作完成后，x 的可能值是（ ）。
A. x=0, x=1, x=2
B. x=0, x=1
C. x=0, x=2
D. x=1, x=2
>[^4]小g讲解知识点

**【答案】** A 

**【解析】**
初始 $x=1$。
*   **情形1 (顺序执行)**：
    *   P1先执行完 ($x=2$)，P2再执行 ($2-1=1$)。结果 $x=1$。
    *   P2先执行完 ($x=0$)，P1再执行 ($0+1=1$)。结果 $x=1$。
*   **情形2 (P1丢失更新)**：
    *   P1读 $x=1$ (R1=1)。
    *   P2读 $x=1$ (R2=1)。
    *   P1执行完 (写回 $x=2$)。
    *   P2执行完 (写回 $x=0$)。
    *   P2覆盖了P1的结果。结果 $x=0$。
*   **情形3 (P2丢失更新)**：
    *   P2读 $x=1$ (R2=1)。
    *   P1读 $x=1$ (R1=1)。
    *   P2执行完 (写回 $x=0$)。
    *   P1执行完 (写回 $x=2$)。
    *   P1覆盖了P2的结果。结果 $x=2$。

综上，可能的结果有 0, 1, 2。

### 二、综合应用题（第45-46题）

#### 45. 题目描述
某银行提供1 个服务窗口和10 个供顾客等待的座位。顾客到达银行时，若有空座位，则到取号机上领取一个号，等待叫号。取号机每次仅允许一位顾客使用。当营业员空闲时，通过叫号选取一位顾客，并为其服务。顾客和营业员的活动过程描述如下：
```c
cobegin
{
    process 顾客i {
        从取号机获取一个号码;
        等待叫号;
        获取服务;
    }
    process 营业员 {
        while(TRUE) {
            叫号;
            为顾客服务;
        }
    }
} coend
```
请添加必要的信号量和P、V（或wait()、signal()）操作，实现上述过程中的互斥与同步。要求写出完整的过程，说明信号量的含义并赋初值。

>小g讲解
>[^5]知识点梳理
>[^6]带领完成题目

**【答案与解析】**

1）互斥资源：取号机（一次只一位顾客领号），因此设一个互斥信号量 mutex。

2）同步问题：顾客需要获得空座位等待叫号，当营业员空闲时，将选取一位顾客并为其服务。空座位的有、无影响等待顾客数量，顾客的有、无决定了营业员是否能开始服务，故分别设置信号量 empty 和 full 来实现这一同步关系。另外，顾客获得空座位后，需要等待叫号和被服务。这样，顾客与营业员就服务何时开始又构成了一个同步关系，定义信号量 service 来完成这一同步过程。

```
semaphore empty   = 10;       // 空座位的数量
semaphore mutex   = 1;        // 互斥使用取号机
semaphore full    = 0;        // 已占座位的数量
semaphore service = 0;        // 等待叫号

process 顾客 i {
    P(empty);                 // 等空位
    P(mutex);                 // 申请使用取号机
    从取号机上取号;
    V(mutex);                 // 取号完毕
    V(fu11);                  // 通知营业员有新顾客
    P(service);               // 等待营业员叫号
    接受服务;
}

process 营业员 {
    while(True) (
        P(fu11);              // 没有顾客则休息
        叫号;
        V(empty);             // 离开座位
        V(service);           // 叫号
        为顾客服务;
    }
}
```

#### 46. 题目描述
某文件系统为一级目录结构，文件的数据一次性写入磁盘，已写入的文件不可修改，但可多次创建新文件。请回答如下问题：
(1) 在连续、链式、索引三种文件的数据块组织方式中，哪种更合适？要求说明理由。为定位文件数据块，需要在FCB 中设计哪些相关描述字段？
(2) 为快速找到文件，对于FCB，是集中存储好，还是与对应的文件数据块连续存储好？要求说明理由。

**【答案与解析】**

**(1) 文件组织方式的选择**
*   **选择**：**连续分配**（Continuous Allocation）方式最合适。
*   **理由**：
    1.  题目条件指出“文件数据一次性写入”且“不可修改”，这意味着文件大小在创建时确定且不再动态增长，不存在连续分配常见的扩展困难问题。
    2.  连续分配支持**顺序访问**和**直接（随机）访问**，读取速度最快（磁头移动距离最短）。
    3.  实现简单，只需要记录起始位置和长度。
*   **FCB设计字段**：
    为了定位文件数据块，FCB（文件控制块）中需要包含：
    1.  **文件的起始物理块号**（Start Block）。
    2.  **文件长度**（Length，即占用的块数）。

**(2) FCB的存储方式**
*   **选择**：**FCB 集中存储**更好。
*   **理由**：
    1.  **检索速度**：文件系统检索文件时，是根据文件名查找FCB。如果将所有FCB集中存放（例如形成一个目录文件或专门的FCB区域），在查找过程中，操作系统可以将包含多个FCB的磁盘块一次性读入内存，从而大大减少磁盘I/O次数。
    2.  若FCB与数据块连续存储，则每个FCB分散在磁盘的不同位置。在遍历目录查找文件时，需要频繁地移动磁头跳转到不同位置读取FCB，导致巨大的寻道时间和I/O开销，检索效率极低。

#### **23. 下列选项中，不可能在用户态发生的事件是（ ）。**

**B.** 外部中断  
**C.** 进程切换  
**D.** 缺页  

**【正确答案】** C  
**【答案解析】**  
本题关键是对“在用户态发生”（与“在用户态执行”区分）的理解。
*   **A项：** 系统调用是操作系统提供给用户程序的接口，系统调用指令（如 `int` 指令）是在用户态下发出的，然后陷入核心态执行。
*   **B项：** 外部中断是用户态到核心态的“门”，中断信号可以在用户态下发生（如外设发出的信号），然后在核心态完成中断处理。
*   **C项：** 进程切换涉及修改进程状态、保存和恢复进程上下文等敏感操作，必须在 **核心态** 下进行，不能在用户态下发生。
*   **D项：** 缺页是在用户程序执行过程中访问内存时发现页面不在内存中而产生的异常，该事件是在用户态执行指令时发生的，随后进入核心态执行缺页中断服务程序。

#### **24. 中断处理和子程序调用都需要压栈以保护现场，中断处理一定会保存而子程序调用不需要保存其内容的是（ ）。**
**A.** 程序计数器  
**B.** 程序状态字寄存器  
**C.** 通用数据寄存器  
**D.** 通用地址寄存器  

**【正确答案】** B  
**【答案解析】**  
*   子程序调用只需保存 **程序断点**（即 `PC` 的内容），以便调用结束后返回。
*   中断处理不仅要保护断点（`PC`），还需要保护 **程序状态字寄存器（PSW）** 的内容，因为中断可能改变系统的状态（如由用户态变为核心态）。
*   通用寄存器在两者中都可能需要保存，视具体实现而定，但 PSW 是中断必须保存而子程序调用通常不涉及的（子程序调用通常不改变特权级和系统状态）。

**A.** 虚拟存储只能基于连续分配技术  
**B.** 虚拟存储只能基于非连续分配技术

#### **26. 操作系统的 I/O 子系统通常由四个层次组成，每一层明确定义了与邻近层次的接口。其合理的层次组织排列顺序是（ ）。**

#### **28. 若一个用户进程通过 read 系统调用读取一个磁盘文件中的数据，则下列关于此过程的叙述中，正确的是（ ）。**
Ⅰ. 若该文件的数据不在内存中，则该进程进入睡眠等待状态  
Ⅱ. 请求 read 系统调用会导致 CPU 从用户态切换到核心态

#### **29. 一个多道批处理系统中仅有 P1 和 P2 两个作业，P2 比 P1 晚 5ms 到达，它们的计算和 I/O 操作顺序如下：**
*   P1：计算 60ms，I/O 80ms，计算 20ms
*   P2：计算 120ms，I/O 40ms，计算 40ms
若不考虑调度和切换时间，则完成两个作业需要的时间最少是（ ）。

**A.** 240ms  
**B.** 260ms  
**C.** 340ms  
**D.** 360ms  

>多道批处理默认单CPU

**【正确答案】** B  
**【答案解析】**  
P1 先到达，先占有 CPU。
*   **0~60ms：** P1 计算（CPU 被 P1 占用）。P2 在 5ms 到达，进入就绪队列等待。
*   **60~140ms：** P1 进行 I/O（80ms）。此时 CPU 空闲，P2 开始计算。
    *   P2 需要计算 120ms，此处只能执行 80ms（60~140ms）。
*   **140ms：** P1 I/O 结束，申请 CPU。由于 P2 还没算完（只算了 80ms，剩 40ms），如果抢占式则 P1 抢占，如果非抢占则 P2 继续。题目求“最少时间”：
	*   **策略1（让 P1 先跑）：**
		140-160: P1 CPU. **P1 结束**。
		160-200: P2 CPU (rest 40ms).
		200-240: P2 I/O (40ms).
		240-280: P2 CPU (40ms). **P2 结束**。总耗时 280ms。
	*   **策略2（让 P2 先跑，题目没说抢占，但求“最少”，看是否有更优）：**
		如果在 140 时让 P2 继续跑完剩下的 40ms（140-180），P1 等待。
		140-180: P2 CPU.
		180: P2 进 I/O (40ms) -> 180-220.
		180-200: CPU 给 P1 (20ms). **P1 结束**。
		220: P2 I/O 结束。
		220-260: P2 CPU (40ms). **P2 结束**。总耗时 **260ms**。
    
    显然策略 2 时间更短。
    **结论：** 260ms。

#### **30. 若某单处理器多进程系统中有多个就绪态进程，则下列关于处理机调度的叙述中，错误的是（ ）。**
**A.** 在进程结束时能进行处理机调度  
**B.** 创建新进程后能进行处理机调度  
**C.** 在进程处于临界区时不能进行处理机调度  
**D.** 在系统调用完成并返回用户态时能进行处理机调度  

**【正确答案】** C  
**【答案解析】**  
*   **C项错误：** 当进程处于 **临界区** 时，它只是在访问临界资源。如果该进程在临界区内长时间运行（例如访问慢速 I/O 设备作为临界资源，或者在临界区内时间片用完），**可以** 进行处理机调度，剥夺其 CPU 使用权，只要不破坏对临界资源的互斥访问规则（如不强行进入被锁定的区）即可。
    *   注意区分：**“临界区”**（访问共享资源的代码段）与 **“原子操作/内核临界区”**（操作系统内核中不可中断的代码）。普通临界区是可以发生调度的，否则一个进程在打印时（临界区）将独占 CPU，这是不合理的。

#### **31. 下列关于进程和线程的叙述中，正确的是（ ）。**
**A.** 不管系统是否支持线程，进程都是资源分配的基本单位  
**B.** 线程是资源分配的基本单位，进程是调度的基本单位  
**C.** 系统级线程和用户级线程的切换都需要内核的支持  
**D.** 同一进程中的各个线程拥有各自不同的地址空间

#### **32. 下列选项中，不能改善磁盘设备 I/O 性能的是（ ）。**
**A.** 重排 I/O 请求次序  
**B.** 在一个磁盘上设置多个分区  
**C.** 预读和滞后写  
**D.** 优化文件物理块的分布  

**【正确答案】** B  
**【答案解析】**  
*   **A项：** 磁盘调度算法（如电梯算法）通过重排请求次序，减少寻道时间，能改善性能。
*   **B项：** **分区** 主要是为了文件系统的逻辑管理（如 C 盘、D 盘），它不能减少物理上的寻道或旋转延迟，反而可能因为数据分散在不同分区（磁道跨度大）而增加寻道时间，**不能改善性能**。
*   **C项：** 预读（Read-ahead）和滞后写（Delayed-write/Buffer）利用缓冲区减少物理 I/O 次数，能改善性能。
	- **预读（Read-ahead）：** 基于**空间局部性（Spatial Locality）**。当进程请求逻辑块 $L_i$ 时，OS 预测它稍后会请求 $L_{i+1}$，于是发起指令一次性读取 $\{L_i, L_{i+1}, ..., L_{i+k}\}$ 进入内存。
	    
	- **滞后写（Delayed-write）：** 当进程请求写逻辑块 $L_j$ 时，OS 仅将其写入内存缓冲区并标记为 Dirty，然后立即返回成功。只有当缓冲区满或定时器到期时，才真正发起物理写操作。
*   **D项：** 优化块分布（如将相关联的块放在相邻磁道）可以减少寻找时间，能改善性能。
	- **差的分布（碎片化）：** $p_1$ 在磁道 10，$p_2$ 在磁道 100，$p_3$ 在磁道 5。读取时磁头乱跳。
	    
	- **优化的分布（簇/连续分配）：** 强制使 $p_i$ 和 $p_{i+1}$ 在物理上相邻（Next Sector）或位于同一个磁道（Same Track）。

#### **45. 题目描述**
某请求分页系统的局部页面置换策略如下：系统从 0 时刻开始扫描，每隔 5 个时间单位扫描一轮驻留集（扫描时间忽略不计），本轮没有被访问过的页框将被系统回收，并放入到空闲页框链尾，其中内容在下一次被分配之前不被清空。当发生缺页时，如果该页曾被使用过且还在空闲页框链表中，则重新放回进程的驻留集中；否则，从空闲页框链表头部取出一个页框。
假设不考虑其他进程的影响和系统开销，初始时进程驻留集为空。目前系统空闲页框链表中页框号依次为 **32、15、21、41**。
进程 P 依次访问的 `<虚拟页号，访问时刻>` 是：
`<1, 1>`、`<3, 2>`、`<0, 4>`、`<0, 6>`、`<1, 11>`、`<0, 13>`、`<2, 14>`。

请回答下列问题：
**(1)** 访问 `<0, 4>` 时，对应的页框号是什么？
**(2)** 访问 `<1, 11>` 时，对应的页框号是什么？说明理由。
**(3)** 访问 `<2, 14>` 时，对应的页框号是什么？说明理由。
**(4)** 该策略是否适合于时间局部性好的程序？说明理由。

>小g
>[^8]知识点梳理
>[^9]带领完成题目

**【答案及解析】**

**分析过程：**
*   **初始状态：** 驻留集为空。空闲链表：32 -> 15 -> 21 -> 41。
*   **T=0：** 扫描开始。
*   **T=1：** 访问 `<1, 1>`。缺页。取空闲链表头 **32**。页 1 装入页框 32。驻留集：{Page 1(Frame 32, used)}。
*   **T=2：** 访问 `<3, 2>`。缺页。取空闲链表头 **15**。页 3 装入页框 15。驻留集：{P1(F32), P3(F15)}。
*   **T=4：** 访问 `<0, 4>`。缺页。取空闲链表头 **21**。页 0 装入页框 21。驻留集：{P1(F32), P3(F15), P0(F21)}。
*   **T=5：** **第一轮扫描**。
    *   检查过去 5 个时间单位（0-5）内的访问情况。
    *   Page 1 (T=1 访问), Page 3 (T=2 访问), Page 0 (T=4 访问)。
    *   所有页都在本轮被访问过，**没有页框被回收**。
    *   驻留集保持：{P1(F32), P3(F15), P0(F21)}。
*   **T=6：** 访问 `<0, 6>`。命中 P0(F21)。
*   **T=10：** **第二轮扫描**。
    *   检查过去 5 个时间单位（5-10）内的访问情况。
    *   Page 0 在 T=6 被访问。保留。
    *   Page 1 上次访问 T=1，本轮（5-10）未访问。**回收 P1(F32)**。F32 放入空闲链表尾。
    *   Page 3 上次访问 T=2，本轮（5-10）未访问。**回收 P3(F15)**。F15 放入空闲链表尾。
    *   此时驻留集：{P0(F21)}。
    *   空闲链表（更新后）：41 -> 32 -> 15。
*   **T=11：** 访问 `<1, 11>`。
    *   页 1 不在驻留集中（T=10 被回收）。发生缺页。
    *   检查策略：该页曾被使用过（在 F32 中）且 F32 还在空闲链表中（链表中为 41, 32, 15）。
    *   **命中空闲链表中的 F32**。将 F32 重新放回驻留集。
    *   驻留集：{P0(F21), P1(F32)}。空闲链表：41 -> 15。
*   **T=13：** 访问 `<0, 13>`。命中 P0(F21)。
*   **T=14：** 访问 `<2, 14>`。
    *   页 2 从未访问过。缺页。
    *   从空闲链表头部取出一个页框。头部是 **41**。
    *   页 2 装入页框 41。
    *   驻留集：{P0(F21), P1(F32), P2(F41)}。

**答案：**
**(1)** **21**。
**(2)** **32**。理由：T=11 时访问页 1，页 1 在 T=10 的扫描中因本轮未被访问而被回收至空闲链表（页框 32）。根据题目策略，当发生缺页时，若该页还在空闲链表中，则将其收回驻留集，故对应页框号仍为 32。
**(3)** **41**。理由：T=14 时访问页 2，页 2 是首次访问，不在驻留集也不在空闲链表的回收记录中。因此从空闲链表头部取出页框 41 分配给它。
**(4)** **合适**。理由：时间局部性好的程序意味着最近被访问过的页面很可能在不久的将来再次被访问。该策略将刚被回收的页面暂存在空闲链表中（类似页面缓冲池），如果程序具有良好的时间局部性，这些页面很快会被再次访问，从而可以快速从空闲链表中找回而不需要从磁盘重新调入，减少了 I/O 开销。

#### **46. 题目描述**
某文件系统空间的最大容量为 4TB（1TB = $2^{40}$ B），以磁盘块为基本分配单位。磁盘块大小为 1KB。文件控制块 (FCB) 包含一个 512B 的索引表区。请回答下列问题。
**(1)** 假设索引表区仅采用直接索引结构，索引表区存放文件占用的磁盘块号，索引表项中块号最少占多少字节？可支持的单个文件最大长度是多少字节？
**(2)** 假设索引表区采用如下结构：第 0～7 字节采用 `<起始块号，块数>` 格式表示文件创建时预分配的连续存储空间，其中起始块号占 6B，块数占 2B；剩余 504 字节采用直接索引结构，一个索引项占 6B，那么可支持的单个文件最大长度是多少字节？为了使单个文件的长度达到最大，请指出起始块号和块数分别所占字节数的合理值并说明理由。

**【答案及解析】**

**(1)**
*   **计算块号所需字节数：**
    *   系统最大容量 4TB，块大小 1KB。
    *   磁盘块总数 = $4\text{TB} / 1\text{KB} = 2^{42} / 2^{10} = 2^{32}$ 个。
    *   要寻址 $2^{32}$ 个磁盘块，块号至少需要 32 位，即 **4 字节**。
*   **计算文件最大长度：**
    *   FCB 索引表区大小 = 512B。
    *   每个索引项（块号）占 4B。
    *   可容纳索引项数 = $512 / 4 = 128$ 个。
    *   每个索引项指向 1 个 1KB 的磁盘块。
    *   最大文件长度 = $128 \times 1\text{KB} = \mathbf{128\text{KB}}$。

**(2)**
*   **计算当前结构下的最大长度：**
    *   **部分1（连续分配区）：**
        *   格式 `<起始块号(6B), 块数(2B)>`。
        *   块数占 2B（16位），最大可表示 $2^{16} = 65536$ 个块。
        *   大小 = $65536 \times 1\text{KB} = 64\text{MB}$。
    *   **部分2（直接索引区）：**
        *   剩余空间 = $512 - 8 = 504$ B。
        *   索引项大小 = 6B。
        *   索引项个数 = $504 / 6 = 84$ 个。
        *   大小 = $84 \times 1\text{KB} = 84\text{KB}$。
    *   **总大小** = $64\text{MB} + 84\text{KB}$。

*   **优化设计：**
    *   要使文件长度达到最大，关键在于利用好 **“连续分配区”**，因为直接索引区的增长是线性的，而连续分配区可以通过增加“块数”字段的位宽来指数级增加寻址范围。
    *   系统总共有 $2^{32}$ 个块。
    *   为了能覆盖整个系统可能的空间或尽可能大的连续空间，**起始块号** 需要能寻址整个磁盘，即需要 **4 字节**（32位，覆盖 $2^{32}$ 块）。
    *   剩余的字节给 **块数**。原预分配区共 8 字节。若起始块号占 4B，则块数占 **4B**。
    *   **合理值：** 起始块号占 **4B**，块数占 **4B**。
    *   **理由：**
        1.  起始块号占 4B 足够寻址整个 4TB 空间（$2^{32}$ 个块）。
        2.  块数占 4B 可以表示 $2^{32}$ 个块，即允许分配的连续空间大小可达 4TB（理论上限）。这样单个文件最大甚至可以占满整个磁盘空间（除去少量直接索引开销）。相比之下，原方案中块数仅 2B，限制了连续空间最大仅 64MB。

	    - 定义：$n \times m$ 的矩阵。

	#### 2. 安全性算法（Safety Algorithm）逻辑
	
	我们要寻找一个**安全序列** $\langle P_1, P_2, ..., P_n \rangle$，使得按照这个顺序，每个进程都能获得所需资源并顺利运行结束。
	
	**形式化步骤如下：**
	
	- **步骤 1（初始化）**：
	    
	    - 设置工作向量 $Work = Available$（表示当前系统能拿出来分配的资源）。
	        
	    - 设置完成向量 $Finish$（长度为 $n$ 的布尔向量），初始化全为 $False$（表示所有进程都没做完）。
	        
	- **步骤 2（寻找可执行进程）**：
	    
	    - 在进程集合中寻找一个满足以下两个条件的进程 $P_i$：
	        
	        1. $Finish[i] == False$ （还没做完）
	            
	        2. $Need_i \le Work$ （当前手头的闲置资源够它用）
	            
	            - _注：向量比较是指每一位都必须小于等于，即 $Need[i, j] \le Work[j]$ 对所有 $j$ 成立。_
	                
	- **步骤 3（回收资源）**：
	    
	    - 如果找到了这样的 $P_i$：
	        
	        - 假设它获得资源、运行结束、归还所有资源。
	            
	        - 更新工作向量：$Work = Work + Allocation_i$
	            
	        - 标记完成：$Finish[i] = True$
	            
	        - 返回**步骤 2**，继续找下一个。
	            
	- **步骤 4（判断结果）**：
	    
	    - 如果所有进程的 $Finish$ 都为 $True$，则系统处于**安全状态**，刚才找到的顺序就是安全序列。
	        
	    - 如果还有进程为 $False$ 但找不到满足条件的 $P_i$，则系统处于**不安全状态**。

[^3]: 假设处理一个数据块涉及三个步骤，时间分别为：
	
	1. **$T$ (Time to Input)**: 从磁盘读入缓冲区的时间。
	    
	2. **$M$ (Move)**: 从缓冲区送入用户区（内存）的时间。
	    
	3. **$C$ (Compute)**: CPU对数据进行计算/分析的时间。
	    
	
	共处理 **$N$** 个数据块。
	
	#### 1. 单缓冲区 (Single Buffer)
	
	**机制**：系统只设一个缓冲区。
	
	- **互斥限制**：当磁盘正在向缓冲区写入数据时（$T$），用户进程不能从缓冲区取走数据（$M$）。即 **$T$ 和 $M$ 是串行的**。
	    
	- **并行机会**：当数据进入用户区后，CPU进行分析（$C$）的同时，磁盘可以开始向缓冲区读入下一块数据（$T$）。即 **$C$ 与下一块的 $T$ 是并行的**。
	    
	
	计算公式：
	
	处理一块数据的平均耗时（流水线稳定后）由“I/O侧耗时”和“CPU侧耗时”的较大者决定：
	
	$$\text{单块时间} = \max(T, C) + M$$
	
	注意：因为 $T$ 和 $M$ 必须串行，所以 I/O 侧的总时间其实是 $T+M$。但在分析流水线时，通常 $C$ 是和下一块的 $T$ 并行的。如果 $C < T$，则 $T$ 是瓶颈；如果 $C > T$，则 $C$ 是瓶颈。
	
	**更精确的通用计算法（针对 $N$ 块）**：
	
	- 如果 $C < T$（CPU算得快）：总时间 = $N \times (T + M) + C$
	    
	    - _解释：每块主要耗时 $T+M$，最后一块分析完多加一个 $C$（因为它是最后一步，没法被覆盖）。_
	        
	- 如果 $C > T$（CPU算得慢）：总时间 = $T + M + N \times C$
	    
	    - _解释：第一块数据准备好需要 $T+M$，之后就是漫长的 $N$ 个 $C$。_
	        
	
	#### 2. 双缓冲区 (Double Buffer)
	
	**机制**：系统设两个缓冲区（Buf1, Buf2）。
	
	- **并行机会**：磁盘向 Buf1 输入数据（$T$）的同时，操作系统可以将 Buf2 的数据传给用户（$M$）并由 CPU 分析（$C$）。
	    
	- **关键点**：此时 $T$ 是独立的一方，而 $(M + C)$ 是另一方。
	    
	
	计算公式：
	
	处理一块数据的平均耗时取决于“生成数据的速度”和“消费数据的速度”谁慢：
	
	$$\text{单块时间} = \max(T, M + C)$$
	
	更精确的通用计算法（针对 $N$ 块）：
	
	$$\text{总时间} \approx T_{\text{first}} + (N-1) \times \max(T, M+C) + (M+C)_{\text{last}}$$
	
	- _解释：第一块需要先读进来($T$)，中间 $N-1$ 块是完美的流水线并行，最后一块需要处理完($(M+C)$)。_
	    
	

[^4]: #### 2. 私有上下文 vs 共享内存（Private Context vs Shared Memory）
	
	这是理解本题最关键的形式化概念：
	
	- **共享变量 ($x$)**：位于物理内存中，所有进程都可以读写它。
	    
	- **私有寄存器 ($R1, R2$)**：
	    
	    - $R1$ 是进程 $P1$ 的私有上下文。
	        
	    - $R2$ 是进程 $P2$ 的私有上下文。
	        
	    - **关键规则**：当进程切换时，CPU 会保存当前进程的寄存器值。也就是说，如果 $P1$ 读取了 $x=1$ 到 $R1$，然后被挂起，即使 $P2$ 修改了内存中的 $x$，等 $P1$ 恢复执行时，$R1$ 里的值依然是旧值 $1$（这就导致了“脏读”或“更新丢失”）。
	        
	
	#### 3. 伯恩斯坦条件与“更新丢失”（Lost Update）
	
	当两个进程并发修改同一个变量，且没有同步机制（如信号量、锁）保护时，就会发生竞态条件。最终的结果取决于“**谁最后执行了 STORE 指令”**。
	
	- 如果是 $P1$ 最后写，结果就是 $P1$ 计算出的值。
	    
	- 如果是 $P2$ 最后写，结果就是 $P2$ 计算出的值。

[^5]: 完成这类题目，你需要掌握三个核心概念：**信号量（Semaphore）**、**P操作（Wait）**、**V操作（Signal）**，以及如何区分**互斥**与**同步**。
	
	#### 1. 信号量 ($S$)
	
	信号量是一个整型变量，用来表示系统中某种资源的数量。
	
	- **非负值** ($S > 0$)：表示当前可用资源的数量。
	    
	- **零值** ($S = 0$)：表示资源刚好用完。
	    
	- **负值** ($S < 0$)：表示资源匮乏，$|S|$ 的绝对值表示正在等待该资源的进程数。
	    
	
	#### 2. P 操作 (Wait / Down)
	
	形式化定义如下：
	
	$$\begin{aligned} & S := S - 1; \\ & \text{if } (S < 0) \text{ then block(current\_process);} \end{aligned}$$
	
	- **含义**：申请资源。
	    
	- **口语理解**：“我要用一个资源。如果减 1 后小于 0，说明刚才已经是 0 了，没有资源了，我就睡觉（阻塞）等待。”
	    
	
	#### 3. V 操作 (Signal / Up)
	
	形式化定义如下：
	
	$$\begin{aligned} & S := S + 1; \\ & \text{if } (S \leq 0) \text{ then wakeup(waiting\_process);} \end{aligned}$$
	
	- **含义**：释放资源。
	    
	- **口语理解**：“我用完了，还回去（加 1）。如果加完后 $S$ 还是小于等于 0，说明刚才 $S$ 是负的，有人在排队等这个资源，那我得去叫醒其中一个。”
	    
	
	#### 4. 互斥 vs. 同步 (解题关键)
	
	- **互斥 (Mutex)**：
	    
	    - **场景**：多个人争抢**同一个**独木桥（取号机）。
	        
	    - **特征**：P 和 V 在**同一个进程**中成对出现（我锁门，我办完事，我开门）。
	        
	    - **初值**：通常为 1。
	        
	- **同步 (Synchronization)**：
	    
	    - **场景**：接力赛。A 跑完 B 才能跑；或者 生产者-消费者（你有空位我才能坐，我有需求你才能干活）。
	        
	    - **特征**：P 和 V 在**不同进程**中出现（顾客 V 通知营业员，营业员 P 收到通知）。
	        
	    - **初值**：通常为 0（表示初始没有消息）或 N（缓冲区大小）。

	```C
	    P(empty);

	    V(mutex);

	    V(full);

	    // 如果营业员没叫（service为0），我就卡在这里。
	    P(service);

	    获取服务;
	}
	```

	```C
	        // 1. 看看有没有人在排队。如果没有(full=0)，我就睡觉休息。
	```

	- 形式化描述：

	    当程序引用地址 $x \in V_{inactive}$ 时，硬件触发**缺页中断（Page Fault）**，操作系统将包含 $x$ 的页面从 $D$ 调入 $M$，并更新页表（Page Table）。

	    为了支持上述机制（按需调页），内存分配必须是离散的（B选项的依据）。如果是连续分配，你无法动态地、零散地将外存中的页面“塞”进物理内存的空隙中。
	    
	
	#### 3. 虚拟存储器的容量限制 (Capacity Constraints)
	
	虚拟存储器的容量分为**最大容量（理论上限）**和**实际容量**。
	
	- 最大容量（逻辑容量）：
	    
	    由 CPU 的寻址范围（Address Bus Width，地址总线宽度）决定。
	    
	    设 CPU 地址总线宽度为 $N$ 位，则虚拟存储器的理论最大容量 $C_{max}$ 为：
	    
	    $$C_{max} = 2^N \text{ Bytes}$$
	    
	    例如：32位系统的理论上限是 4GB，64位系统则是 $2^{64}$ Bytes。
	    
	- 实际容量：
	    
	    受限于物理资源的综合上限。
	    
	    $$C_{actual} = \min(2^N, \text{内存容量} + \text{外存容量})$$
	    
	    注意： 题目中的 C 和 D 选项往往通过强调“只受...限制”来设置陷阱。

	这道题描述的是一种**带有缓冲池的定期扫描置换策略**。我们可以将其逻辑抽象为以下几个核心机制：
	
	#### 1. 系统状态定义
	
	- **$T$ (Time)**: 当前时刻。
	    
	- **$RS$ (Resident Set)**: 驻留集，当前进程已分配的页框集合。
	    
	- **$FL$ (Free List)**: 空闲页框链表，用于存放可分配的页框。链表有**头（Head）和尾（Tail）**。
	    
	- **$Page.Frame$**: 虚拟页号对应的物理页框号。
	    
	
	#### 2. 核心机制的形式化描述
	
	**A. 扫描与回收机制 (Scavenging / Scanning)**
	
	- **触发条件**: $T \mod 5 == 0$ (每隔5个时间单位)。
	    
	- 逻辑:
	    
	    对于 $RS$ 中的每一个页面 $P$：
	    
	    - 如果 $P$ 在 $(T-5, T]$ 时间段内被访问过 $\rightarrow$ **保留 (Keep)**。
	        
	    - 如果 $P$ 在 $(T-5, T]$ 时间段内**未**被访问 $\rightarrow$ **回收 (Reclaim)**。
	        
	        - 操作：$RS = RS - \{P\}$;
	            
	        - 操作：$FL.append(P.Frame)$; // 放入空闲链表尾部
	            
	        - **关键点**: 页框内的内容**保留**，不立即清空。
	            
	
	B. 缺页处理机制 (Page Fault Handling)
	
	当进程访问页面 $P$，且 $P \notin RS$ 时，触发缺页中断：
	
	- **情况 1：软缺页 (Soft Page Fault / Rescue)**
	    
	    - 条件：$P$ 曾经被使用过 $\land$ $P.Frame \in FL$ (页框还在空闲链表中)。
	        
	    - 操作：
	        
	        - 从 $FL$ 中移除该特定页框 $P.Frame$。
	            
	        - $RS = RS + \{P\}$ (将该页框重新加回驻留集)。
	            
	    - _意义：利用“页面缓冲”救回了刚被淘汰的页，避免了昂贵的磁盘I/O。_
	        
	- **情况 2：硬缺页 (Hard Page Fault / Allocation)**
	    
	    - 条件：上述情况不满足 (新页 或 页框已被重用)。
	        
	    - 操作：
	        
	        - $NewFrame = FL.pop\_head()$ (从链表头部取)。
	            
	        - $RS = RS + \{Page \to NewFrame\}$。

	#### 1. 寻址空间模型 (Addressing Space Model)
	
	文件系统管理磁盘时，将物理磁盘划分为一个个小的单元，称为**磁盘块（Block）**。
	
	- **总容量 ($C_{total}$)**: 磁盘能存储的总字节数。
	    
	- **块大小 ($S_{block}$)**: 操作系统分配存储空间的最小单位。
	    
	- 块总数 ($N_{blocks}$): 磁盘中包含的块的数量。
	    
	    $$N_{blocks} = \frac{C_{total}}{S_{block}}$$
	    
	- 寻址位宽 ($W_{addr}$): 为了能唯一标识每一个磁盘块，块号（指针）至少需要的比特数。
	    
	    $$W_{addr} = \lceil \log_2(N_{blocks}) \rceil \text{ (bits)}$$
	    
	    转换成字节通常向上取整：$\text{Bytes} = \lceil W_{addr} / 8 \rceil$。
	    
	
	#### 2. 索引结构模型 (Index Structure Model)
	
	FCB（文件控制块）中的索引表区用于记录文件数据块在磁盘上的位置。
	
	- **A. 直接索引 (Direct Indexing)**
	    
	    - 结构：一个数组，每个元素是一个“块号”。
	        
	    - 容量计算：
	        
	        $$N_{entries} = \lfloor \frac{S_{table}}{S_{ptr}} \rfloor$$
	        
	        $$MaxFileSize = N_{entries} \times S_{block}$$
	        
	    - 其中 $S_{table}$ 是索引表区大小，$S_{ptr}$ 是单个块号占用的字节数。
	        
	- **B. 连续分配/范围索引 (Extent-based Allocation)**
	    
	    - 结构：采用 `<起始块号, 块数>` 二元组表示一段连续的空间。
	        
	    - **起始块号 ($Start$)**: 指向这一段连续空间的第一个块。其位宽决定了该段空间可以位于磁盘的什么位置（定位能力）。
	        
	    - **块数 ($Length$)**: 表示这段空间连续有多少个块。其位宽决定了这一段空间最大能有多大（扩展能力）。
	        
	    - 容量计算：
	        
	        $$MaxFileSize = (2^{Bits_{length}} - 1) \times S_{block}$$
	        
	        (注：假设直接使用位宽能表示的最大无符号整数)
