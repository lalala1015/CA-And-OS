### **二、知识点清单（逐条）**

#### **第一部分：进程管理**

##### **1.1 进程模型**

3.  **进程的概念**
    *   **定义/解释**：老师给出了多个角度的定义，强调其抽象性。
        *   一个程序的一个执行体。
        *   资源分配的一个实体。
        *   一段程序运行起来的状态。
        *   是为了解决并发问题（CPU交替执行）而做的一种抽象，用于实现现场保存和恢复。
    *   **来源标注**：`[录音 t=2:20-3:00] [PPT p=4]`

4.  **进程引入的四个特性**
    *   **定义/解释**：
        *   **虚拟 (Virtual)**：进程以为自己独占了CPU和内存，但实际上CPU是分时复用，内存是通过页表虚拟化的。设备、文件系统也是通过函数接口封装的虚拟概念。
        *   **并发 (Concurrent)**：多个进程在单个CPU上交替执行，以提升效率。
        *   **共享 (Shared)**：多个进程分时复用设备和内存等资源。
        *   **不确定 (Nondeterministic)**：作为应用程序开发者，无法预知调度发生的精确时刻和顺序。
    *   **常见坑/易混淆点**：老师对“不确定性”做了补充：某些特定的调度算法（如实验中做的“积分牌”调度算法）可以是确定性的。这不是一个绝对的概念。
    *   **来源标注**：`[录音 t=3:22-4:55] [PPT p=4]`

5.  **并发与并行**
    *   **定义/解释**：
        *   **并发 (Concurrency)**：宏观上并行，微观上串行。在一个CPU核心上交替执行。
        *   **并行 (Parallelism)**：宏观微观都是并行，需要多个CPU核心同时执行多个任务。
    *   **典型例子/类比**：PPT p5用图示区分了两者。A、B事件在并行图中是完全重叠的，在并发图中是交错的。
    *   **相关考点/可能题型**：并发并没有让单个程序的执行速度变快（因为CPU只有一个），其收益在于：
        1.  **提升用户体验**：对于I/O密集型任务（如点鼠标），能快速得到响应。
        2.  **对计算密集型任务意义不大**：如果一个任务可以持续占用CPU（如科学计算、“炼丹”），频繁的并发切换（如时间片轮转）反而会降低效率。
    *   **来源标注**：`[录音 t=3:00-5:50] [PPT p=5]`

##### **1.2 进程实现**

6.  **进程五状态迁移模型**
    *   **定义/解释**：一个将进程分类的状态机，PPT p7展示了新、就绪、运行、阻塞、退出五个状态。
    *   **关键公式/规则/步骤**：老师详细解释了每条边的触发原因：
        *   **新 -> 就绪 (Admit)**：创建新进程，如 `fork()` 和 `exec()`。
        *   **就绪 -> 运行 (Dispatch)**：调度器选择一个进程运行，执行 `switch_to`。
        *   **运行 -> 阻塞 (Wait)**：进程发起系统调用（`syscall`），如请求I/O。
        *   **运行 -> 就绪 (Timeout)**：时间片用完，发生时钟中断。
        *   **阻塞 -> 就绪 (Event Occurs)**：等待的事件完成，如磁盘读完数据，发生设备中断（DMA中断、键盘中断等）。
        *   **运行 -> 退出 (Release)**：调用 `exit()`、`main`函数结束、或发生致命错误（如除以零）。
    *   **相关考点/可能题型**：这是非常核心的考点，需要理解每个状态转换的具体操作系统事件。
    *   **来源标注**：`[录音 t=6:40-8:15] [PPT p=7]`

7.  **挂起 (Suspend) 状态**
    *   **定义/解释**：为了缓解内存压力，将进程的**所有**页面（包括用户态、内核态页面，甚至PCB）都换出到磁盘上。
    *   **典型例子/类比**：老师用“**笔记本电脑盖子扣上了**”来类比挂起。为了省电，内存会被断电，所以必须把所有东西存到磁盘。
    *   **常见坑/易混淆点**：
        *   **挂起 vs 阻塞**：阻塞状态的进程，可能只有**部分**不活跃的页面被换出到磁盘，大部分数据仍在内存中。而挂起状态的进程，**所有**数据都在磁盘上，在操作系统看来就像“一块墓碑”，不参与调度。
        *   **为什么要挂起就绪进程**：就绪队列过长会增加调度算法的时间开销（O(n)或O(log n)），并且就绪进程本身也消耗内核内存资源。
    *   **来源标注**：`[录音 t=8:20-11:15] [PPT p=8, 9, 59]`

8.  **进程调度算法**
    *   **定义/解释**：从就绪队列中选择一个进程运行的策略。
        *   **先来先服务 (FCFS)**：公平、简单，但对I/O密集型任务不友好。
        *   **短任务优先 (SJF)** / **剩余时间短任务优先 (SRTF)**：理论最优，但难以预测执行时间。
        *   **时间片轮转 (RR)**：目前操作系统使用最广的方法，旨在提升交互性。可以和所有其他算法结合。
        *   **优先级调度**：根据外部或内部赋予的优先级进行调度。
    *   **常见坑/易混淆点**：对于纯计算密集型服务器，时间片轮转是不好的选择。FCFS、SJF、优先级等非抢占或长周期的算法更合适。
    *   **来源标注**：`[录音 t=5:50-6:17, 12:30-14:30] [PPT p=10]`

9.  **调度算法评价指标**
    *   **定义/解释**：
        *   **CPU使用率**：CPU处于忙状态的时间百分比。
        *   **吞吐量**：单位时间内完成的进程数量。
        *   **周转时间**：进程从初始化到结束（包括等待）的总时间。
        *   **等待时间**：进程在就绪队列中的总时间。
        *   **响应时间**：从提交请求到产生响应所花费的总时间。
    *   **相关考点/可能题型**：老师暗示不会单纯考概念记忆，但可能会在计算题中给出定义，让你计算。例如，计算周转时间。
    *   **来源标注**：`[录音 t=15:30] [PPT p=11]`

##### **1.3 进程切换（上下文切换）**

10. **进程切换的概念与机制**
    *   **定义/解释**：暂停当前运行进程，保存其状态（上下文），并加载另一个进程的状态使其运行。这是操作系统的“机制”，而调度算法是“策略”。
    *   **关键公式/规则/步骤**：
        1.  当前进程因`syscall`或中断失去运行权。
        2.  操作系统保存其上下文（寄存器、CPU状态、内存地址空间信息）到其PCB中。
        3.  运行调度算法，选择下一个进程。
        4.  从下一个进程的PCB中恢复其上下文。
        5.  新进程开始执行。
    *   **来源标注**：`[录音 t=16:15] [PPT p=12, 13]`

11. **地址空间切换的实现细节**
    *   **定义/解释**：在进程切换时，需要切换内存地址空间，这通常通过修改页表基址寄存器（如x86的CR3）实现。
    *   **关键公式/规则/步骤**：在ucore代码示例中，先执行 `lcr3(next->cr3)` 切换页表，再执行 `switch_to(...)` 切换寄存器上下文。
    *   **常见坑/易混淆点**：**为什么可以先切换地址空间，再切换寄存器上下文而不出错？**
        *   **答案**：因为所有进程的**内核空间**是共享和统一的。`switch_to`本身是内核代码，无论当前页表指向哪个用户空间，它所在的内核地址都是一样的，所以不会出错。这是设计上的一个权衡，带来了便利也带来了安全隐患。
    *   **来源标注**：`[录音 t=19:40-20:50] [PPT p=16, 49]`

12. **上下文切换与TLB/Cache的关系**
    *   **定义/解释**：切换地址空间（写CR3寄存器）时，硬件会自动使TLB失效，因为旧的地址映射关系已经无用。
    *   **常见坑/易混淆点**：
        *   **TLB**：在x86上，写入CR3会自动刷新TLB。
        *   **Cache**：对于Cache，情况更复杂。老师提到，在早期的80386模拟器上没有Cache，所以不用管。在现代有Cache的系统中，需要考虑Cache一致性问题，通常也需要刷新或特殊处理。
    *   **来源标注**：`[录音 t=21:00-22:15] [PPT p=16]`

13. **调度的代价**
    *   **定义/解释**：上下文切换是有开销的，包括保存/恢复寄存器、陷入/退出内核态的固定开销（安全检查等）。
    *   **典型例子/类比**：老师用“听音乐会前的安检”类比进出内核态的开销，说明安全检查耗时。
    *   **相关考点/可能题型**：对于计算密集型任务，过多的上下文切换（如5个线程在4核CPU上运行）会导致总运行时间显著增加，因为调度开销远大于并行带来的收益。
    *   **来源标注**：`[录音 t=22:20-23:15] [PPT p=17]`

##### **1.4 进程间通信 (IPC)**

14. **IPC方式与代价**
    *   **定义/解释**：由于进程地址空间隔离，通信需要OS介入。常见方式有信号、管道、消息队列、共享内存。
    *   **常见坑/易混淆点**：除共享内存外，其他IPC方式通常涉及多次数据拷贝和**序列化/反序列化**，开销很大。
        *   **序列化**：将复杂数据结构（如树、对象）转换成可以传输的字节流（如数组）。
        *   **反序列化**：从字节流恢复成原始数据结构。
    *   **来源标注**：`[录音 t=23:20-26:50] [PPT p=18]`

15. **共享内存 (Shared Memory)**
    *   **定义/解释**：效率最高的IPC方式。OS将同一块物理内存映射到不同进程的虚拟地址空间中。
    *   **关键公式/规则/步骤**：为了避免指针失效问题，一个关键技术是让这块共享内存在不同进程中的**虚拟地址起始位置也相同**。这样，一个进程在共享区内创建的包含指针的数据结构，可以被另一个进程直接使用。
    *   **来源标注**：`[录音 t=26:50-28:20] [PPT p=18]`

##### **1.5 线程**

16. **线程的概念**
    *   **定义/解释**：线程是进程的一部分，是CPU调度的基本单位。进程是资源分配的基本单位。
        *   同一进程内的线程共享地址空间、文件等资源。
        *   每个线程有自己独立的PC（程序计数器）、SP（栈指针）、寄存器集合和栈（TCB - Thread Control Block）。
    *   **来源标注**：`[PPT p=20]`

17. **用户级线程 (ULT) vs 内核级线程 (KLT)**
    *   **定义/解释**：
        *   **ULT (User-Level Thread)**：线程的管理（创建、切换）完全在用户空间完成，内核不知道线程的存在。
            *   **优点**：切换快，不需陷入内核。
            *   **缺点**：一个线程阻塞（如`syscall`），整个进程的所有线程都会被阻塞。无法利用多核。
        *   **KLT (Kernel-Level Thread)**：线程的管理由内核完成，每个线程都有一个内核数据结构与之对应。
            *   **优点**：一个线程阻塞不影响其他线程；可以被调度到不同核心上，实现并行。
            *   **缺点**：线程切换需要陷入内核，开销大。
    *   **技术演进**：老师讲解了技术演进的螺旋上升过程：早期只有ULT -> 为解决ULT阻塞问题发展出KLT（现代主流OS） -> 为解决KLT切换开销大问题，又回到用户空间，发展出**协程/纤程**。
    *   **来源标注**：`[录音 t=28:20-30:30] [PPT p=21, 22]`

18. **协程 (Coroutine) / 纤程 (Fiber)**
    *   **定义/解释**：在KLT基础上，在用户空间实现的更轻量级的调度单位。它在用户态完成上下文切换，避免了进出内核的开销。
    *   **常见坑/易混淆点**：协程解决了早期ULT的阻塞问题，因为它结合了编译器的支持，不允许在协程上下文中直接调用会阻塞的`syscall`。
    *   **来源标注**：`[录音 t=30:30-31:25] [PPT p=23]`

#### **第二部分：并发与同步**

19. **临界区 (Critical Section)**
    *   **定义/解释**：指一段在同一时刻只允许一个线程（或进程）执行的代码。这不是一个语言或系统特性，而是**程序员之间的约定**，需要通过同步机制来强制实现。
    *   **来源标注**：`[录音 t=35:10-36:45] [PPT p=24, 25]`

20. **用信号量实现互斥 (Mutex)**
    *   **定义/解释**：为保证临界区只有一个执行者。
    *   **关键公式/规则/步骤**：
        1.  初始化一个信号量 `mutex`，其值为 `1`。
        2.  进入临界区前，执行 `P(mutex)` 操作（信号量减1，若小于0则阻塞）。
        3.  执行临界区代码。
        4.  退出临界区后，执行 `V(mutex)` 操作（信号量加1，若有等待者则唤醒一个）。
    *   **常见坑/易混淆点**：P/V操作必须成对、按序出现。不遵守约定的程序员可以直接跳过P操作进入临界区，破坏整个同步机制。老师提到，面向对象的封装（将临界区设为private，提供包含P/V操作的public方法）是解决此问题的常用方法。
    *   **来源标注**：`[录音 t=38:00-39:30] [PPT p=26]`

21. **用信号量实现同步 (Synchronization)**
    *   **定义/解释**：保证事件发生的先后顺序（A做完，B才能做）。
    *   **典型例子/类比**：老师用“挖坑”和“种树”来类比，必须先挖好坑才能种树。
    *   **关键公式/规则/步骤**：
        1.  初始化一个信号量 `condition`，其值为 `0`。
        2.  先行者（A，挖坑）完成其工作后，执行 `V(condition)`。
        3.  后继者（B，种树）在开始其依赖性工作前，执行 `P(condition)`。如果此时V操作未执行，B将在此阻塞。
    *   **来源标注**：`[录音 t=39:30-40:30] [PPT p=27]`

22. **十字路口问题（信号量设计）**
    *   **题目在考什么**：使用信号量解决一个实际的互斥和死锁问题。
    *   **常用解题套路/步骤**：
        1.  **识别资源**：路口的4个交叉块是互斥资源，每个可以看作一个信号量，初值为1。
        2.  **分析动作**：一辆车通过需要依次申请两个资源（如`P(BlockB)`，`P(BlockG)`）。
        3.  **识别死锁风险**：这构成了“哲学家就餐问题”的经典模型。如果4辆车同时到达，各自占有第一个资源并等待第二个，就会发生死锁。
        4.  **设计解决方案**：
            *   **破坏循环等待**：按统一顺序申请资源（不适用于此场景）。
            *   **破坏占有并等待**：一次性申请所有资源（`P(B)`和`P(G)`必须是原子操作）。
            *   **限制进入者数量**：老师给出的思路是，观察到最多3辆车在路口不会死锁，因此可以增加一个全局信号量 `enter_road`，初值为3，进入路口前先P操作，离开后V操作。
    *   **来源标注**：`[录音 t=31:30-32:50] [PPT p=28-31]`

23. **多核乱序执行与内存屏障**
    *   **定义/解释**：在多核处理器上，为提高性能，指令的执行顺序可能与代码顺序不一致（乱序执行），这会导致依赖于指令顺序的同步算法（如Peterson、Dekker算法）失效。
    *   **典型例子/类比**：PPT p33的例子，CPU0的 `flag = true;` 可能会被乱序到 `c = 3;` 之前执行，导致CPU1在`c`还未初始化时就进入`do_something`，引发错误。
    *   **常见坑/易混淆点**：
        *   Peterson和Dekker算法在理论上（单核）是正确的，但在现代多核CPU上是**错误**的，不能使用。
        *   解决乱序执行问题需要使用**内存屏障**(Memory Fence/Barrier)指令，强制在此之前的写操作对其他核心可见。
        *   x86处理器的内存模型较强，能保证某些顺序，不易出错。而ARM、RISC-V等处理器内存模型较弱，更容易出现乱序问题。
    *   **来源标注**：`[录音 t=34:30-36:30] [PPT p=33]`

#### **第三部分：系统调用与保护机制**

24. **保护机制：用户态与内核态**
    *   **定义/解释**：为了保护操作系统内核不被应用程序破坏，并实现对硬件资源的安全管理，现代CPU实现了多种保护级别。操作系统利用其中的两种：
        *   **用户态 (User Mode)**：应用程序运行的状态，权限受限，不能执行特权指令，不能直接访问硬件。
        *   **内核态 (Kernel Mode / Supervisor Mode)**：操作系统内核运行的状态，拥有最高权限，可以执行所有指令，访问所有内存和硬件。
    *   **关键公式/规则/步骤**：这种保护是硬件、内存、指令三个层面的结合：
        1.  **CPU状态**：CPU内部有一个状态位/寄存器，标识当前处于用户态还是内核态。
        2.  **内存保护**：页表项中有保护位（U/S位），标记该内存页是否允许在用户态下访问。
        3.  **指令保护**：某些指令被定义为“特权指令”，只能在内核态执行（如关中断、修改页表寄存器）。
    *   **来源标注**：`[录音 t=36:30-37:10] [PPT p=34]`

25. **系统调用 (System Call) 的本质与过程**
    *   **定义/解释**：系统调用是操作系统提供给应用程序的接口，是应用程序请求内核服务的唯一合法途径。它本质上是一个由OS提供的函数，其执行过程伴随着从用户态到内核态的权限切换。老师强调，这是一个“**用户程序可以主动发起的中断**”。
    *   **关键公式/规则/步骤**：
        1.  **参数准备 (用户态)**：应用程序将**系统调用编号**放入一个约定的寄存器（如x86的`%eax`），并将函数参数按约定放入其他寄存器或压入栈中。
        2.  **陷入 (Trap)**：应用程序执行一条特殊的“陷入指令”，如x86的 `int` 或RISC-V的 `ecall`。
        3.  **权限提升与跳转 (硬件)**：CPU硬件响应陷入指令，自动完成：(a) 将CPU状态从用户态切换到内核态；(b) 保存当前PC等少量上下文；(c) 跳转到操作系统预设在中断向量表中的中断处理程序入口。
        4.  **服务分发与执行 (内核态)**：内核的中断处理程序根据系统调用编号，在系统调用表中找到并执行对应的内核函数（服务例程）。
        5.  **返回**：内核函数执行完毕后，执行一条特殊的“从中断返回”指令，如x86的 `iret` 或RISC-V的 `sret`。
        6.  **权限恢复 (硬件)**：CPU硬件响应返回指令，自动将CPU状态从内核态恢复为用户态，并返回到用户程序陷入指令的下一条指令继续执行。
    *   **相关考点/可能题型**：练习题2考察了系统调用的正确执行顺序：`③传递参数 -> ②执行陷入指令 -> ④执行服务程序 -> ①返回用户态`。
    *   **来源标注**：`[录音 t=37:10-38:30] [PPT p=34, 35, 36, 78]`

26. **系统调用的代价**
    *   **定义/解释**：系统调用开销很大。
    *   **常见坑/易混淆点**：代价大的原因不仅仅是寄存器保存和恢复，更重要的是：
        1.  **权限切换**：进出内核态本身有固定的硬件开销。
        2.  **安全检查**：内核必须对用户传入的所有参数进行严格的合法性和安全性检查，以防恶意攻击。
        3.  **上下文清理**：为了安全，进出内核时可能需要清理硬件状态（如缓存），防止信息泄露。
    *   **来源标注**：`[录音 t=38:30-39:00] [PPT p=35]`

#### **第四部分：内存管理**

27. **地址关系与转换**
    *   **定义/解释**：
        *   **虚拟地址 (Virtual Address)**：程序员和编译器使用的地址，存在于进程的独立地址空间中。
        *   **线性地址 (Linear Address)**：在x86分段+分页模型中，是虚拟地址经过段部件转换后的中间地址。在现代扁平内存模型中，虚拟地址通常就等于线性地址。
        *   **物理地址 (Physical Address)**：内存硬件实际使用的地址，对应内存条上的物理位置。
        *   **转换过程**：虚拟地址 -> (段部件) -> 线性地址 -> (页部件/MMU) -> 物理地址。
    *   **来源标注**：`[PPT p=37]`

28. **连续内存管理**
    *   **定义/解释**：早期内存管理方式，为每个进程分配一块连续的物理内存。
        *   **动态分区分配**：根据进程大小动态划分分区。
        *   **问题**：会产生外部碎片（小的、不连续的空闲块）。
        *   **解决方案**：**紧缩 (Compaction)**，通过移动进程来合并碎片，但开销巨大。
    *   **常见坑/易混淆点**：老师提到，这种方式因为**没有MMU地址翻译的开销**，理论上访存效率更高，因此现代一些研究开始“考古”式地重新审视该技术。
    *   **来源标注**：`[录音 t=39:30-40:30] [PPT p=38, 39, 40]`

29. **页式内存管理与多级页表**
    *   **定义/解释**：将虚拟地址空间和物理内存都划分为大小固定的块，分别称为**页** (Page)和**页框 (Page Frame)**。**页表 (Page Table)**记录了虚拟页到物理页框的映射关系。
    *   **多级页表**：为了解决单级页表在巨大虚拟地址空间下自身体积过大的问题，将页表本身也进行分页，形成树状结构。
        *   **32位系统 (经典二级)**：地址 `10(页目录) + 10(页表) + 12(偏移)`，设计非常“完美”。
        *   **64位系统 (现代四级)**：由于页大小仍为4KB，而地址项变为8字节，一个页只能存512个表项（2^9），所以地址结构变为 `9+9+9+9+12`，设计上不如32位优雅。
    *   **相关考点/可能题型**：需要具备页表的设计和地址翻译推导能力。
    *   **来源标注**：`[录音 t=40:50-42:30] [PPT p=42, 44, 45]`

30. **快表 (TLB - Translation Lookaside Buffer)**
    *   **定义/解释**：一个用于缓存近期使用过的页表项的高速硬件缓存，位于MMU中，用于加速地址翻译。
    *   **关键公式/规则/步骤**：
        1.  MMU收到虚拟地址后，**并行地**进行两项操作：
            *   用虚拟页号在TLB中查找。
            *   开始在内存中进行多级页表的查询。
        2.  **TLB命中 (Hit)**：直接从TLB获取物理页框号，取消内存中的页表查询，快速计算出物理地址。
        3.  **TLB未命中 (Miss)**：等待内存中页表查询的结果，得到物理页框号后，将其填入TLB（可能会替换掉一个旧表项），再计算物理地址。
    *   **来源标注**：`[录音 t=42:30-43:00] [PPT p=46]`

31. **大页 (Huge Pages)**
    *   **定义/解释**：使用比标准4KB更大的页面（如2MB, 1GB），通过在多级页表查询中提前终止来实现。
    *   **常见坑/易混淆点**（优缺点分析）：
        *   **优点**：
            1.  **减少MMU查询时间**：页表查询层级减少。
            2.  **节省TLB项**：一个TLB表项可以映射更大的内存区域。
            3.  **可能节省内存**：省去了下级的页表所占用的内存。
        *   **缺点**：
            1.  **可能浪费内存**：如果程序只使用大页的一小部分，会造成严重的内部碎片。
            2.  **破坏兼容性**：许多软件和系统设计都基于4KB页的假设。
    *   **来源标注**：`[录音 t=43:40-45:30] [PPT p=47]`

32. **缺页异常 (Page Fault) 与处理流程**
    *   **定义/解释**：当程序访问一个在页表中标记为无效（即不在物理内存中）的虚拟页面时，由MMU硬件触发的一种异常。
    *   **关键公式/规则/步骤**：(见PPT p50详细图解)
    *   **常见坑/易混淆点**：发生需要从磁盘读取数据的缺页异常后，进程的状态会从**运行态**变为**阻塞态**，等待磁盘I/O完成。
    *   **来源标注**：`[录音 t=46:00-47:00] [PPT p=50]`

33. **页面置换算法**
    *   **定义/解释**：当发生缺页异常且没有空闲物理页框时，用于选择一个“牺牲”页面将其换出到磁盘的算法。
    *   **常见算法**：
        *   **最优 (OPT/MIN)**：替换未来最长时间不被访问的页（理论最优，无法实现）。
        *   **先进先出 (FIFO)**：替换最早进入内存的页。简单但性能不佳，可能产生Belady现象。
        *   **最近最少使用 (LRU)**：替换最久未被使用的页。性能好，但实现开销大。
        *   **时钟 (Clock) / NRU (Not Recently Used)**：LRU的近似实现，通过访问位(R)和修改位(M)来选择牺牲页。
        *   **工作集 (Working Set)**：认为进程在一段时间内访问的页面集合是相对固定的，换出不在当前工作集内的页面。
    *   **相关考点/可能题型**：老师强调要会**推演算法的过程**，是计算题的常见题型。
    *   **来源标注**：`[录音 t=46:00] [PPT p=51, 52]`

34. **抖动 (Thrashing)**
    *   **定义/解释**：当系统中的并发进程数过多，导致分配给每个进程的物理内存严重不足，进程在运行中频繁发生缺页，系统大部分时间都在进行页面换入换出，而不是有效计算，导致CPU利用率急剧下降的现象。
    *   **典型例子/类比**：老师生动地描述了其恶性循环过程：进程A缺页阻塞 -> 进程B运行，为腾空间换出A的页 -> 进程B也缺页阻塞 -> 进程A恢复运行，发现自己的页又没了，再次缺页... 陷入“大家都在抢内存”的局面。
    *   **解决方案**：降低并发度，即撤销（或挂起）部分进程。
    *   **来源标注**：`[录音 t=47:00-48:40] [PPT p=54]`

35. **Belady 现象**
    *   **定义/解释**：对于某些页面置换算法（如FIFO），分配给进程的物理页框数增加，缺页次数反而增加的异常现象。
    *   **常见坑/易混淆点**：这违背了直觉。LRU、OPT等“栈算法”不会出现此现象。
    *   **来源标注**：`[录音 t=48:50] [PPT p=55]`

#### **第五部分：文件系统与设备管理**

36. **文件物理结构**
    *   **定义/解释**：文件在磁盘上存放的三种方式：
        *   **连续分配**：文件占一组连续的磁盘块。优点是读写快，支持随机访问；缺点是外部碎片和文件不易扩展。
        *   **链式分配 (Link Table)**：文件块通过指针链接起来，像链表。优点是无外部碎片，文件易扩展；缺点是只能顺序访问，可靠性差。
        *   **索引分配 (Index Table)**：使用一个索引块（i-node）存放所有数据块的地址。优点是支持随机访问，无外部碎片，易扩展；缺点是索引块本身占用空间。
    *   **典型例子/类比**：老师将索引分配类比为内存管理中的页表。
    *   **来源标注**：`[录音 t=50:20-51:00] [PPT p=61, 62, 63]`

37. **磁盘访问时间**
    *   **定义/解释**：一次磁盘读写操作的时间由三部分构成：
        1.  **寻道时间 (Seek Time)**：移动磁臂到目标磁道的时间。**通常是主要矛盾**。
        2.  **旋转延迟 (Rotational Latency)**：等待目标扇区旋转到磁头下的时间。
        3.  **传输时间 (Transfer Time)**：数据从磁盘读出或写入的时间。
    *   **来源标注**：`[录音 t=51:00-51:30] [PPT p=64, 67]`

38. **磁盘调度算法**
    *   **定义/解释**：用于决定处理磁盘I/O请求队列顺序的算法，主要目标是减少总的寻道时间。
    *   **常见算法**：
        *   **FCFS (先来先服务)**：公平但效率低。
        *   **SSTF (最短寻道时间优先)**：优先处理离当前磁头最近的请求，可能导致“饥饿”。
        *   **SCAN (电梯算法)**：磁头在一个方向上移动，服务所有沿途请求，到底后反向。
        *   **C-SCAN (循环扫描)**：只在一个方向上服务请求，到底后直接返回起始端再开始扫描。
    *   **常见坑/易混淆点**：老师提到，在现代系统中，磁盘调度很多时候由硬盘控制器自己完成，操作系统层面的调度算法应用减少。
    *   **来源标注**：`[录音 t=51:30-52:20] [PPT p=68, 69]`

39. **设备通信模式**
    *   **定义/解释**：CPU与I/O设备交互的三种基本方式：
        *   **忙等待 (Busy Waiting) / 轮询**：CPU反复查询设备状态寄存器，直到设备就绪。浪费CPU。
        *   **中断 (Interrupt)**：CPU启动I/O后就去执行其他任务，设备完成后通过中断信号通知CPU。
        *   **DMA (Direct Memory Access)**：直接内存访问。CPU只需设置DMA控制器（源、目的地址、长度），之后由DMA控制器完成内存与设备间的数据传输，完成后再中断通知CPU。这极大地解放了CPU。
    *   **老师的综合视角**：老师将这些模式归纳为两类操作的组合：
        1.  **发现数据**的方式：轮询 vs. 中断。
        2.  **传输数据**的方式：CPU传输 vs. DMA传输。
        并补充了第四种现代高性能模式：**CPU轮询发现数据 + DMA传输数据**。
    *   **来源标注**：`[录音 t=52:50-54:00] [PPT p=71, 72, 73, 74]`

40. **死锁 (Deadlock)**
    *   **定义/解释**：两个或多个进程因互相等待对方持有的资源而都无法继续执行的僵持状态。
    *   **四种处理策略**：
        1.  **预防 (Prevention)**：破坏死锁产生的四个必要条件之一。
        2.  **避免 (Avoidance)**：在分配资源前判断是否会进入不安全状态，如银行家算法。
        3.  **检测与解除 (Detection & Recovery)**：允许死锁发生，定时检测并解除（如剥夺资源、终止进程）。
        4.  **忽略 (Ignore)**：鸵鸟算法。
    *   **老师观点**：老师强调实际系统中最常用的就是**忽略**（鸵鸟算法），因为死锁预防和避免的代价太高，而死锁在多数系统中发生概率很低。
    *   **来源标注**：`[录音 t=54:40-55:00] [PPT p=76, 77]`

### **5道可能的简答题题干 + 参考要点**

1.  **简述操作系统处理缺页中断（Page Fault）的完整流程。**
    *   **参考要点**：
        1.  CPU访存，MMU查页表发现页表项无效，触发缺页异常（中断）。
        2.  CPU从用户态切换到内核态，执行OS的异常处理程序。
        3.  OS检查访问的虚拟地址是否合法。若非法，则终止进程。
        4.  OS查找该页在磁盘（交换空间）上的位置。
        5.  在物理内存中寻找一个空闲页框。若无空闲页框，则执行页面置换算法，选择一个牺牲页。
        6.  若有牺牲页，将其内容写回磁盘（如果它被修改过，即“脏页”）。并更新其页表项为无效。
        7.  从磁盘将所需页面读入找到的空闲页框中。
        8.  更新引发缺页的进程的页表，填入物理页框号，并将有效位置1。
        9.  从内核态返回用户态，重新执行刚才引发异常的指令。

2.  **比较用户级线程（ULT）和内核级线程（KLT）的优缺点。并解释为何现代操作系统中出现了协程（Coroutine）。**
    *   **参考要点**：
        *   **ULT**：优点是切换速度快（不需内核干预）；缺点是一个线程阻塞会导致整个进程阻塞，且无法利用多核处理器。
        *   **KLT**：优点是内核可见，可独立调度，一个阻塞不影响其他，可利用多核；缺点是切换开销大（需陷入内核）。
        *   **协程出现原因**：为了兼具两者的优点。它在内核级线程的基础上，于用户空间实现更轻量级的上下文切换，避免了KLT频繁进出内核的高昂代价，从而获得极高的并发性能。这是技术“螺旋上升”的体现。

3.  **什么是“抖动”（Thrashing）？请解释其产生的原因及恶性循环过程。**
    *   **参考要点**：
        1.  **定义**：系统中并发进程数过多，导致分配给每个进程的物理页框严重不足，使得进程在运行中频繁发生缺页，大部分时间都在进行页面换入换出，而不是有效计算，导致CPU利用率急剧下降的现象。
        2.  **原因**：根本原因是并发度超出了物理内存的承载能力。
        3.  **恶性循环**：进程A运行 -> 缺页 -> 阻塞并等待IO -> OS调度进程B -> 进程B运行，为腾出空间可能换出进程A的页 -> 进程B也缺页 -> 阻塞... -> 进程A的IO完成，回到就绪队列 -> 被调度运行，发现自己的页又被换出，再次缺页。所有进程都在重复这个过程，CPU大部分时间处于空闲等待IO的状态。

4.  **请解释在进程上下文切换时，为什么可以先切换目标进程的地址空间（如修改CR3寄存器），再切换CPU的寄存器上下文（如调用`switch_to`），而不会导致程序执行错误？**
    *   **参考要点**：
        1.  该操作发生在内核态，执行的是内核代码。
        2.  现代操作系统设计中，所有进程共享一个**相同且统一的内核地址空间**。
        3.  当执行`lcr3`指令切换到新进程的页表时，虽然用户地址空间变了，但当前指令指针（PC）仍在内核空间，这部分地址在新旧页表中的映射是完全一样的。
        4.  因此，后续的`switch_to`等内核代码可以继续在正确的地址上执行，直到完成寄存器上下文的切换，最终返回到新进程的用户空间。

5.  **在使用信号量解决并发问题时，“互斥”和“同步”的典型实现模式有何不同？请分别说明其信号量初始值设置的原则。**
    *   **参考要点**：
        *   **互斥（Mutex）**：用于保护临界区，保证同一时间只有一个进程进入。
            *   **模式**：`P(mutex) -> Critical Section -> V(mutex)`。
            *   **初始值**：信号量初值设为 **1**，表示资源（临界区访问权）只有一个。
        *   **同步（Synchronization）**：用于保证进程间的执行有特定的先后顺序。
            *   **模式**：后继者进程执行 `P(condition)` 等待条件满足，先行者进程在完成工作后执行 `V(condition)` 触发条件。
            *   **初始值**：信号量初值设为 **0**，表示条件初始时不满足（或资源数量为0）。

### **5道可能的计算/推导/过程题题干 + 解题框架**

1.  **磁盘调度算法计算**
    *   **题干**：一个磁盘有200个磁道（0-199），当前磁头在53号磁道，正在向磁道号增加的方向移动。现有一个请求队列为：98, 183, 37, 122, 14, 124, 65, 67。请分别计算使用SSTF、SCAN、C-SCAN调度算法的总寻道距离。
    *   **解题框架**：
        *   **SSTF (最短寻道时间优先)**：
            1.  从当前位置53开始，找距离最近的请求。`abs(65-53)=12`, `abs(37-53)=16`，选择65。移动12。
            2.  当前在65，找最近的。选择67。移动2。
            3.  当前在67，找最近的。选择37。移动30。
            4.  ... 依次计算，直到队列为空。将每一步的移动距离相加。
        *   **SCAN (电梯算法)**：
            1.  当前在53，向磁道号增加方向移动。依次服务路径上的请求：65, 67, 98, 122, 124, 183。
            2.  到达199号磁道（或者最后一个请求183之后就掉头，取决于LOOK还是SCAN，题目为SCAN则到199）。
            3.  改变方向，向磁道号减小方向移动。依次服务路径上的请求：37, 14。
            4.  将所有移动距离相加：`(199 - 53) + (199 - 14)`。
        *   **C-SCAN (循环扫描)**：
            1.  同SCAN，从53向增加方向移动，服务65, 67, ..., 183。
            2.  到达199号磁道。
            3.  **立即**返回到0号磁道，这个过程不服务任何请求。
            4.  从0号磁道开始，再向增加方向移动，服务路径上的请求：14, 37。
            5.  将所有服务过程中的移动距离相加：`(199 - 53) + (199 - 0) + (37 - 0)`。

2.  **页面置换算法推演**
    *   **题干**：一个进程分配到4个物理页框，其页面访问序列为：1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5。请分别画出使用FIFO和LRU页面置换算法时的页面置换过程，并计算缺页次数。
    *   **解题框架**：
        1.  画一个表格，行表示物理页框（4行），列表示页面访问序列的每一步。
        2.  **FIFO (先进先出)**：
            *   依次填入1, 2, 3, 4。发生4次缺页。
            *   访问1, 2：命中。
            *   访问5：缺页。替换最先进入的页面 **1**。
            *   访问1：缺页。替换最先进入的页面 **2**。
            *   ... 维护一个进入队列，每次替换队首元素。
        3.  **LRU (最近最少使用)**：
            *   依次填入1, 2, 3, 4。发生4次缺页。
            *   访问1, 2：命中。每次命中时，将被访问的页面标记为“刚刚使用”。
            *   访问5：缺页。检查当前页框中的4个页面（1,2,3,4），发现页面 **3** 是最久未被使用的，替换它。
            *   ... 维护每个页面的“上次使用时间”，每次替换最久未使用的。
        4.  统计两种算法下“缺页”标记的总数。

3.  **银行家算法安全性检查**
    *   **题干**：某系统有资源A、B、C，数量分别为(10, 5, 7)。在T0时刻，有P0-P4五个进程，其资源分配情况如下表。请问：1）T0时刻是否安全？请给出安全序列。2）若此时P1请求(1, 0, 2)个资源，系统是否可以分配？为什么？
| 进程 | Max (最大需求) | Allocation (已分配) | Need (尚需) |
| :-- | :-- | :-- | :-- |
| P0 | (7, 5, 3) | (0, 1, 0) | (7, 4, 3) |
| P1 | (3, 2, 2) | (2, 0, 0) | (1, 2, 2) |
| P2 | (9, 0, 2) | (3, 0, 2) | (6, 0, 0) |
| P3 | (2, 2, 2) | (2, 1, 1) | (0, 1, 1) |
| P4 | (4, 3, 3) | (0, 0, 2) | (4, 3, 1) |
    *   **解题框架**：
        1.  **计算Available向量**：Available = Total - Sum(Allocation) = (10, 5, 7) - (7, 2, 5) = (3, 3, 2)。
        2.  **运行安全性算法**：
            *   初始化Work = Available = (3, 3, 2)，Finish = (false, false, false, false, false)。
            *   找一个`i`满足 `Finish[i]==false` 且 `Need[i] <= Work`。
            *   P1: `Need(1,2,2) <= Work(3,3,2)` -> 满足。执行P1，`Work += Allocation[P1] = (3,3,2)+(2,0,0)=(5,3,2)`。Finish=true。安全序列 `<P1...`
            *   P3: `Need(0,1,1) <= Work(5,3,2)` -> 满足。执行P3，`Work += Allocation[P3] = (5,3,2)+(2,1,1)=(7,4,3)`。Finish=true。安全序列 `<P1, P3...`
            *   ... 继续查找，直到所有进程都Finish=true。若能找到，则系统安全，给出该序列。若找不到这样的进程，则不安全。
        3.  **处理P1的请求**：
            *   **检查1**: `Request(1,0,2) <= Need[P1](1,2,2)`？是。
            *   **检查2**: `Request(1,0,2) <= Available(3,3,2)`？是。
            *   **试分配**：`Available' = Available - Req = (2,3,0)`。`Allocation[P1]' = Alloc[P1] + Req = (3,0,2)`。`Need[P1]' = Need[P1] - Req = (0,2,0)`。
            *   **再次运行安全性算法**：用新的`Available'`和进程状态表，重复第2步。如果新状态是安全的，则可以分配；否则，不能分配，P1需等待。

4.  **文件系统i-node计算**
    *   **题干**：某文件系统的簇（块）大小为4KB，每个地址项大小为4B。文件索引节点（i-node）中有8个直接地址项，1个一级间接地址项，1个二级间接地址项。请问该文件系统支持的最大文件长度是多少？
    *   **解题框架**：
        1.  **计算一个簇能存多少个地址项**：`4KB / 4B = 1024` 个地址项。
        2.  **计算直接地址项能表示的大小**：`8个 * 4KB/个 = 32 KB`。
        3.  **计算一级间接地址项能表示的大小**：1个一级间接块可以存放1024个地址项，每个地址项指向一个4KB的数据块。所以大小为 `1024 * 4KB = 4 MB`。
        4.  **计算二级间接地址项能表示的大小**：1个二级间接块存放1024个地址项，每个地址项指向一个一级间接块。所以总大小为 `1024 * (一级间接表示的大小) = 1024 * 4MB = 4 GB`。
        5.  **求和**：最大文件长度 = 直接 + 一级间接 + 二级间接 = `32KB + 4MB + 4GB`。

5.  **虚拟地址到物理地址转换过程**
    *   **题干**：在一个32位系统中，采用二级页表进行地址翻译，虚拟地址空间4GB，页面大小4KB。虚拟地址`0x00403004`，一级页表（页目录）的基址在物理地址`0x100000`。请描述MMU将该虚拟地址翻译为物理地址的完整步骤（可假设中间查到的页表项内容）。
    *   **解题框架**：
        1.  **地址结构划分**：
            *   页面大小4KB = 2^12 B，所以页内偏移 (Offset) 占12位。
            *   32位地址，剩下 `32 - 12 = 20` 位用于页号。
            *   二级页表，20位平均分配，所以一级页号（PT1）10位，二级页号（PT2）10位。
            *   地址结构为：`PT1 (10 bits) | PT2 (10 bits) | Offset (12 bits)`。
        2.  **解析虚拟地址**：
            *   `0x00403004` 的二进制为 `0000 0000 0100 0000 0011 0000 0000 0100`。
            *   PT1: `0000 0000 01` (二进制) = `1` (十进制)。
            *   PT2: `00 0000 0011` (二进制) = `3` (十进制)。
            *   Offset: `0000 0000 0100` (二进制) = `4` (十进制)。
        3.  **翻译过程**：
            *   **第一步：查一级页表**。
                *   一级页表基址为 `0x100000`。
                *   要找的页目录项（PDE）的索引是PT1 = 1。假设每个页表项占4字节。
                *   PDE的物理地址 = `0x100000 + 1 * 4 = 0x100004`。
                *   从该地址读取PDE内容。**假设**读出的值为`0x200007` (包含二级页表基址和状态位)。
            *   **第二步：查二级页表**。
                *   从PDE中提取二级页表的基址。假设状态位表示有效，基址为 `0x200000`。
                *   要找的页表项（PTE）的索引是PT2 = 3。
                *   PTE的物理地址 = `0x200000 + 3 * 4 = 0x20000C`。
                *   从该地址读取PTE内容。**假设**读出的值为`0x300007` (包含物理页框号和状态位)。
            *   **第三步：计算最终物理地址**。
                *   从PTE中提取物理页框号（页帧号）。假设基址为 `0x300000`。
                *   最终物理地址 = 页框基址 + 页内偏移 = `0x300000 + 0x004 = 0x300004`。
