# 参考答案与解析

### 一、选择题

1.  **A (先来先服务)**
    *   **解析**：时间片轮转 (RR) 算法中，如果时间片设得无限大，每个进程都能一次执行完毕，就等同于按照到达顺序执行，即退化为 FCFS。
2.  **C (就绪态 $\rightarrow$ 阻塞态)**
    *   **解析**：进程只有在**运行**时才能发出系统调用（如I/O请求）从而进入阻塞态。就绪态的进程没有占用 CPU，无法执行指令进入阻塞状态。
3.  **B**
    *   **解析**：覆盖技术 (Overlay) 的主要特点是需要程序员手动规划覆盖结构，将不会同时执行的模块共享同一块内存区域。它不需要硬件支持虚拟内存 (A错)，不能自动管理 (C错)，且因为频繁装入/卸载模块会增加 I/O (D错)。
4.  **D (或 B)**
    *   **解析**：
        *   A 正确，Peterson 是纯软件算法。
        *   B 说法较为主观，但在现代 OS 内核中，自旋锁 (Spinlock) 和互斥锁 (Mutex) 使用极其广泛，信号量通常用于同步而非简单的互斥。若题目认为 B 是错的，可能是因为“远超”这个量词。但 D 的错误更明显。
        *   C 正确，TAS 指令是硬件原子指令。
        *   D **错误**。竞争条件 (Race Condition) 的定义是“多个进程并发访问和操作同一数据且执行结果与访问发生的特定顺序有关”。描述中提到“调度变得零碎”表述不准确，竞争的本质是**缺乏互斥保护导致的交错执行**，而非调度本身的碎片化。
        *   *注：结合试卷手写标记，学生选了 B，但 D 的描述在学术上更存在定义性偏差。*
5.  *(题目缺失)*
6.  **(需具体计算)**
    *   **思路**：这道题考察混合页表结构。
    *   如果是一个完整的两级页表，通常顶级页表全覆盖。这里只有 512 个 PDE 指向二级表，256 个指向大页。
    *   计算需知：每个页表本身占用的空间。通常一个页表占 1页 (4KB)。
    *   总空间 = 顶级页表大小 (4KB) + (512个二级页表 $\times$ 4KB/个)。
    *   *注：因题目关键数字被遮挡，无法给出确切数值。*
7.  **A (FIFO)**
    *   **解析**：Belady 异常是指在 FIFO 算法中，分配的物理页帧数增加，缺页率反而可能上升的现象。LRU 和最优算法 (OPT) 这种堆栈类算法不会出现此现象。
8.  **D (数据库文件的访问)**
    *   **解析**：预取机制依赖于**局部性原理**（特别是空间局部性）。
        *   A (数组连续) 空间局部性极好，利于预取。
        *   B (局部性高) 利于预取。
        *   D (数据库随机访问) 数据库查询往往涉及随机磁盘块读取，空间连续性差，预取命中率低，不利于预取。
9.  **C (235)**
    *   **解析**：
        *   当前磁头：100。方向：由大向小。
        *   队列：19, 23, 45, 67, 89, 20, 173, 108, 134, 40。
        *   小于100的部分排序：89, 67, 45, 40, 23, 20, 19。
        *   大于100的部分排序：108, 134, 173。
        *   路径：100 $\rightarrow$ 19 (并不去0，因为不达两端)。
        *   距离1：$100 - 19 = 81$。
        *   转向后：19 $\rightarrow$ 173。
        *   距离2：$173 - 19 = 154$。
        *   总距离：$81 + 154 = 235$。
10. **D**
    *   **解析**：**北桥** (Northbridge) 芯片通常连接 CPU、内存和显卡，负责高速数据传输；**南桥** (Southbridge) 连接硬盘、USB、音频等较慢的设备。选项 D 说南桥善于处理速度较快设备，刚好说反了。

**12. 文件系统计算**

1.  **文件 A 占用物理块数：**
    *   总大小 = $384 \text{ records} \times 255 \text{ B/record} = 97,920 \text{ B}$。
    *   块大小 = 512 B。
    *   块数 = $\lceil 97920 / 512 \rceil = \lceil 191.25 \rceil = 192$ 块。
    *   *注：这里假设记录是紧凑存放的（Byte stream），如果记录不能跨块存放，则是 $512/255 = 2$ 个记录/块，需要 $384/2 = 192$ 块。结果一致。*

2.  **目录与 Inode：**
    *   **目录的本质**：目录也是一种文件，其内容是一张映射表，记录了该目录下所有文件名与对应的 FCB (或 inode 编号) 的对应关系。
    *   **Inode 的作用**：Inode (索引节点) 存储了文件的元数据 (Metadata)，包括文件大小、权限、所有者、时间戳以及指向文件数据块的指针。它不包含文件名。

3.  **链式存储读取次数：**
    *   读取 `/root/document/log/A`。
    *   1. 读根目录 `/` 的 inode 和数据块 (找到 document 的 inode 号)。
    *   2. 读 `document` 的 inode 和数据块 (找到 log 的 inode 号)。
    *   3. 读 `log` 的 inode 和数据块 (找到 A 的 inode 号)。
    *   4. 读 `A` 的 inode (获取 A 的第一个盘块地址)。
    *   5. **读取 A 的数据**：由于是链式存储 (Linked Allocation)，不支持随机访问，必须从第 1 块读到第 192 块。
    *   **总次数**：目录解析开销 (约 3-4 次读，视缓存而定) + 192 次数据块读取。重点在于链式存储需要顺序读取全部数据块。

4.  **索引存储 (Indexed Allocation) 占用块数：**
    *   文件数据占用 192 块。
    *   索引块计算：假设地址占 4B (32位系统常见)。
    *   一个物理块 (512B) 可存索引项数：$512 / 4 = 128$ 个。
    *   文件有 192 个数据块，需要 192 个索引项。
    *   $192 > 128$，因此需要 2 个索引块 (或者使用多级索引)。
    *   **总块数** = 192 (数据) + 2 (索引) = **194 块**。

5.  **优化方案 (针对碎片化)：**
    *   **方案**：**磁盘碎片整理 (Defragmentation)** 或采用 **成组链接法/位示图** 结合更优的分配策略。
    *   **设计理由**：
        *   **碎片整理**：通过移动文件块，将同一个文件的物理块在磁盘上连续存放。这极大地利用了磁盘 I/O 的顺序访问特性，减少了磁头寻道时间和旋转延迟，从而提高读取效率。
        *   **日志结构文件系统 (LFS)**：所有写入都追加到日志末尾，将随机写转换为顺序写，解决写入效率问题，但在读取时可能仍需索引。
