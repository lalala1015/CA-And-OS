
## 题 1（反推参数）：四段地址序列 + 命中率 → 推断 cache 组织与替换策略

**题目**  
某处理器有一个数据 cache。对每个“地址序列”执行完后，你只能观测到**该序列的 cache hit ratio**（命中率）。  
已知条件与取值范围（按题面给定）：
- 相联度：1 / 2 / 4 ways  
- 块大小：1 / 2 / 4 / 8 / 16 / 32 bytes  
- 总 cache 大小：256B 或 512B  
- 替换策略：LRU 或 FIFO  
- 假设：所有访问都是 **1 byte 访问**，地址是 **byte address**；**每个序列开始时 cache 都是空的**。

给定四条序列与命中率：

1. 序列 1：`[0, 2, 4, 8, 16, 32]`，Hit Ratio = `0.33`
2. 序列 2：`[0, 512, 1024, 1536, 2048, 1536, 1024, 512, 0]`，Hit Ratio = `0.33`
3. 序列 3：`[0, 64, 128, 256, 512, 256, 128, 64, 0]`，Hit Ratio = `0.33`
4. 序列 4：`[0, 512, 1024, 0, 1536, 0, 2048, 512]`，Hit Ratio = `0.25`

**要求**  
推断该 cache 的：
- 相联度  
- 块大小  
- 总大小  
- 替换策略（LRU / FIFO）  
并写出推断过程。

# 答案
第一题（四段地址序列 + 命中率）的**标准答案**在 UT Austin 的 Problem Set 4 官方解答里能直接查到：最终 cache 参数为

- **块大小（Block size）= 8 bytes** ([用户论坛](https://users.ece.utexas.edu/~patt/13s.460N/probs/ps4/ps4sol.html "EE 460N: Problem Set 4 Solution"))
    
- **相联度（Associativity）= 4-way** ([用户论坛](https://users.ece.utexas.edu/~patt/13s.460N/probs/ps4/ps4sol.html "EE 460N: Problem Set 4 Solution"))
    
- **总 cache 大小（Total cache size）= 256 B** ([用户论坛](https://users.ece.utexas.edu/~patt/13s.460N/probs/ps4/ps4sol.html "EE 460N: Problem Set 4 Solution"))
    
- **替换策略（Replacement policy）= LRU** ([用户论坛](https://users.ece.utexas.edu/~patt/13s.460N/probs/ps4/ps4sol.html "EE 460N: Problem Set 4 Solution"))
    

下面按四个序列把推断过程（你自己也能复现）简要写一遍：

---

## 1）用序列 1 锁定块大小 = 8B

序列 1：`0, 2, 4, 8, 16, 32`，命中率 0.33 = 2/6。  
解答中把不同 block size 的可达到命中数列成表：只有当 **block size=8B** 时，命中数刚好是 **2/6**（地址 2 和 4 与地址 0 落在同一个 8B 块里，所以能 hit，其余都 miss）。因此块大小确定为 8B。 ([用户论坛](https://users.ece.utexas.edu/~patt/13s.460N/probs/ps4/ps4sol.html "EE 460N: Problem Set 4 Solution"))

---

## 2）用序列 2 锁定相联度 = 4-way

序列 2：`0, 512, 1024, 1536, 2048, 1536, 1024, 512, 0`，命中率 0.33 = 3/9。

关键观察：这些地址都是 **512 的倍数**。而 cache 总大小只可能是 256B 或 512B，所以这些地址会**映射到同一个 set**（解答里直接给出这一结论）。这样它就变成“同一 set 里竞争”的问题：

- 若 direct-mapped（1-way），第二次回访不可能出现 3 次 hit（解答算出最多 0/9）。
    
- 若 2-way，最多也只能 1/9。
    
- 若 4-way，可以达到 3/9，且与观测吻合，因此相联度 = 4-way。 ([用户论坛](https://users.ece.utexas.edu/~patt/13s.460N/probs/ps4/ps4sol.html "EE 460N: Problem Set 4 Solution"))
    

---

## 3）用序列 3 锁定总容量 = 256B

序列 3：`0, 64, 128, 256, 512, 256, 128, 64, 0`，命中率 0.33 = 3/9。

在已经知道 **block=8B、4-way** 的前提下：

- 若总容量是 **256B**：set 数 = 256/(8\*4)=8（也就是 3 个 index bit），解答指出这串地址会映射到同一个 set，并且 hit/miss 恰好给出 **3/9**。
    
- 若总容量是 **512B**：set 数=16（4 个 index bit），同样推一遍会得到更高的命中（解答展示会出现 4/9 的情况）。
    

因此总容量只能是 **256B**。 ([用户论坛](https://users.ece.utexas.edu/~patt/13s.460N/probs/ps4/ps4sol.html "EE 460N: Problem Set 4 Solution"))

---

## 4）用序列 4 区分替换策略：LRU 而不是 FIFO

序列 4：`0, 512, 1024, 0, 1536, 0, 2048, 512`，命中率 0.25 = 2/8。

在 **block=8B、4-way、256B** 都已确定后，唯一剩下的是替换策略：

- 若是 **FIFO**，解答把该序列的 hit/miss 推出来是 `M M M H M H M H`，命中率 **3/8**，不符合观测 0.25。
    
- 若是 **LRU**，hit/miss 为 `M M M H M H M M`，命中率 **2/8 = 0.25**，与观测一致，因此替换策略是 **LRU**。 ([用户论坛](https://users.ece.utexas.edu/~patt/13s.460N/probs/ps4/ps4sol.html "EE 460N: Problem Set 4 Solution"))





这是一个非常关键的步骤。在这个阶段，我们已经确定了**Block Size = 8 Bytes** 和 **Associativity = 4-way**，剩下的任务是在 **256B** 和 **512B** 两个总容量选项中二选一。

我们需要通过**序列 3** 的模拟执行来验证哪一个容量能产生 **3/9** 的命中率。

以下是这一步的详细推演过程：

---

### 前置已知条件

从前两步我们已经锁定：

1. **Block Size ($B$) = 8 Bytes**
    
2. **Associativity ($E$) = 4-way** (4 路组相联)
    

### 待验证的假设

题目给了两个总容量选项，我们需要分别计算它们的**Set（组）数量**，看看地址是如何映射的。

- **假设 A：Total Size = 256 Bytes**
    
    - Set 数量 ($S$) = $\frac{\text{Total Size}}{\text{Block Size} \times \text{Associativity}} = \frac{256}{8 \times 4} = \frac{256}{32} = \mathbf{8 \text{ Sets}}$
        
    - **Index 计算方法**：地址除以 8 后，对 **8** 取余（即看二进制的第 3-5 位）。
        
- **假设 B：Total Size = 512 Bytes**
    
    - Set 数量 ($S$) = $\frac{512}{32} = \mathbf{16 \text{ Sets}}$
        
    - **Index 计算方法**：地址除以 8 后，对 **16** 取余（即看二进制的第 3-6 位）。
        

---

### 序列 3 详细模拟

序列 3 地址流：0, 64, 128, 256, 512, 256, 128, 64, 0

总访问次数：9 次。

目标命中率：$0.33 \approx 3/9$（即 3 次命中，6 次未命中）。

#### 场景一：假设总容量为 256 Bytes (8 Sets)

我们需要计算每个地址映射到哪个 Set。

- **地址映射计算** (Address % TotalBlocks):
    
    - $0$: $0 / 8 = 0 \to 0 \mod 8 = \mathbf{Set\ 0}$
        
    - $64$: $64 / 8 = 8 \to 8 \mod 8 = \mathbf{Set\ 0}$
        
    - $128$: $128 / 8 = 16 \to 16 \mod 8 = \mathbf{Set\ 0}$
        
    - $256$: $256 / 8 = 32 \to 32 \mod 8 = \mathbf{Set\ 0}$
        
    - $512$: $512 / 8 = 64 \to 64 \mod 8 = \mathbf{Set\ 0}$
        
    
    **关键发现**：在 256B 容量下，**所有地址都映射到了 Set 0**。这会造成激烈的冲突。
    
- Cache 状态演变 (Set 0, 容量 4 个 Block)：
    
    (注：此时 LRU 和 FIFO 在驱逐谁的问题上效果一致，因为 0 是最早进入的)
    
    1. **访问 0**：Miss (Cache为空)。
        
        - Set 0: `[0, -, -, -]`
            
    2. **访问 64**：Miss (Tag不同)。
        
        - Set 0: `[0, 64, -, -]`
            
    3. **访问 128**：Miss。
        
        - Set 0: `[0, 64, 128, -]`
            
    4. **访问 256**：Miss。
        
        - Set 0: `[0, 64, 128, 256]` **(Set 0 已满！)**
            
    5. **访问 512**：Miss。
        
        - **发生冲突**：必须驱逐一个块。0 是最早进来的（也是最久未使用的），**驱逐 0**。
            
        - Set 0: `[64, 128, 256, 512]`
            
    6. **访问 256**：**Hit** (在 Cache 中)。
        
        - Set 0: `[64, 128, 256, 512]` (如果是 LRU，256 更新为最新)
            
    7. **访问 128**：**Hit**。
        
        - Set 0: `[64, 128, 256, 512]`
            
    8. **访问 64**：**Hit**。
        
        - Set 0: `[64, 128, 256, 512]`
            
    9. **访问 0**：**Miss**。
        
        - 原因：0 在第 5 步为了给 512 腾位置被驱逐了。
            
        - Set 0: `[0, 128, 256, 512]` (驱逐了 64)
            
- **统计结果**：
    
    - Hits: 3 次 (即访问 256, 128, 64 时)
        
    - Total: 9 次
        
    - Hit Ratio: **3/9**
        
    - **结论：符合题目给定的 0.33。**
        

---

#### 场景二：假设总容量为 512 Bytes (16 Sets)

为了证明 256B 是唯一答案，我们必须证明 512B 是错的。

在 16 Sets 的情况下，Index 是 (Address / 8) % 16。

- **地址映射计算**：
    
    - $0$: $0 \to \mathbf{Set\ 0}$
        
    - $64$: $64 / 8 = 8 \to 8 \mod 16 = \mathbf{Set\ 8}$ <-- **注意！地址 64 去了 Set 8**
        
    - $128$: $16 \mod 16 = \mathbf{Set\ 0}$
        
    - $256$: $32 \mod 16 = \mathbf{Set\ 0}$
        
    - $512$: $64 \mod 16 = \mathbf{Set\ 0}$
        
    
    **关键区别**：地址 `64` 独自去了 Set 8，不参与 Set 0 的拥挤竞争。Set 0 只处理 `0, 128, 256, 512` 这 4 个地址。
    
- **Cache 状态演变**：
    
    **Set 8 的状态**：
    
    - 访问 64 (第2步): **Miss** -> 存入 64。
        
    - 访问 64 (第8步): **Hit**。
        
    
    **Set 0 的状态 (处理 0, 128, 256, 512)**：
    
    - Set 0 容量为 4，而映射到这里的地址也是 4 个 (0, 128, 256, 512)。**这意味着刚好填满，不需要驱逐任何人！**
        
    
    1. 访问 0: **Miss** -> Set 0: `[0]`
        
    2. (访问 64 去 Set 8 了，跳过 Set 0)
        
    3. 访问 128: **Miss** -> Set 0: `[0, 128]`
        
    4. 访问 256: **Miss** -> Set 0: `[0, 128, 256]`
        
    5. 访问 512: **Miss** -> Set 0: `[0, 128, 256, 512]` **(满，但未溢出)**
        
    6. 访问 256: **Hit**。
        
    7. 访问 128: **Hit**。
        
    8. (访问 64 去 Set 8 了，Hit)
        
    9. 访问 0: **Hit**。 (0 从未被驱逐，因为它依然在 Cache 里)
        
- **统计结果**：
    
    - Set 0 Hits: 3 次 (256, 128, 0)
        
    - Set 8 Hits: 1 次 (64)
        
    - Total Hits: 4 次
        
    - Hit Ratio: **4/9** (约 0.44)
        
    - **结论：不符合题目给定的 0.33。**
        

---

### 最终推断结论 (Step 3 Conclusion)

只有当总容量为 **256 Bytes** 时，地址 `64` 才会因为 Index 位不够多而卷入 Set 0 的冲突，导致 Set 0 超载（5 个地址争夺 4 个位置），进而迫使最早的地址 `0` 被驱逐，最终导致最后一次访问 `0` 时发生 Miss，将命中数限制在 3/9。

因此，**Cache Total Size = 256 Bytes**。
