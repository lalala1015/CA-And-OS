### 一、简单流水线（考的较少，重概念）

**1. 核心思想**
*   **答案**：将指令执行过程分解为多个阶段（Stage），让多条指令在不同阶段重叠执行（并行），核心目的是**提升指令吞吐量**（Throughput），而不是减少单条指令的执行时间。

**2. 两个关键原因**
*   **Q1: 为什么流水线时钟周期时间 > (单周期CPU的时钟周期时间 / 级数)？**
    *   **答案**：
        1.  **流水线寄存器延迟**：每个阶段之间增加了流水线寄存器用于保存中间结果，会有建立时间和传输延迟。
        2.  **阶段不平衡**：时钟周期必须迁就**最慢**的那个阶段（关键路径）。
        3.  **额外开销**：为了处理冒险等问题，增加了控制逻辑、前递旁路等电路的延迟。
*   **Q2: 为什么 CPI > 1？**
    *   **答案**：理想情况下 CPI=1，但实际上存在**危害（Hazards）**（如数据依赖、跳转指令），导致流水线必须暂停（Stall）或冲刷，浪费了周期。

**3. 指令相关性与危害（Hazards）**
*   **危害定义**：导致下一条指令无法在下一个时钟周期执行的情况。
*   **真相关（True Dependence）**：
    *   **RAW (写后读)**：必须等待前一条指令产生结果。这是真正的依赖，无法完全消除，只能通过Forwarding缓解。
*   **假相关（False Dependence）**：
    *   **WAW (写后写)** 和 **WAR (读后写)**：这是由于寄存器**名字复用**引起的。可以通过**寄存器重命名**（在乱序执行章节提到）来消除。
*   **结构相关**：硬件资源冲突（如同时访问内存）。在流水线中，多条指令同时处于不同的阶段。如果两条不同的指令，在**同一个时钟周期**内，试图去使用**同一个硬件部件**，就会发生冲突。
*   **控制相关**：分支指令导致无法确定下一条指令。**还没决定好要不要跳转，流水线就已经把后面的指令取进来了**。

### 二、存储层次（【重点】必考大题）
**基本概念**
- **块 (Block / Cache Line)**：Cache 中最小的数据管理单元。数据以块为单位在主存和 Cache 之间来回复制。

- **Cache Line (缓存行) —— “存储容器”**：
	- “块 (Block)”是**数据内容**。而 **行 (Line)** 是用来存放这些数据的**物理容器（槽位）**。
	- 它是Cache 中**最小的物理存储单元**，不仅仅包含从内存拷贝来的数据（Block），还必须包含管理这些数据所需的**元数据 (Metadata)**。
	- $$\text{Cache Line} = \text{Valid Bit (有效位)} + \text{Tag (标记)} + \text{Data Block (数据块)}$$
	- _(如果是写回策略，可能还有 Dirty Bit 脏位)_
	
	- **关键点**：
		- **Block vs. Line**：虽然平时混着用，但严格来说，**Block 是内容（只有数据），Line 是容器（数据 + 标签 + 状态位）**。
		- 当我们说“Cache 有 64KB”时，通常指的是**Data Block**的总容量，不算 Tag 和 Valid Bit 占用的额外空间。
- **Set (组) —— “索引单位”**：Set 是一个逻辑上的集合，包含**一行或多行** Cache Line。
	- **作用**：它是**地址索引 (Index)** 的直接目标。
	- 当地址中的 `Index` 字段确定后，硬件就锁定了唯一的**一个组**。
	- 接下来的查找操作（比较 Tag），**只在这个组内部进行**。
	- **关键点**：
		- **Index 决定去哪个 Set**。
		- **Tag 决定是 Set 里的哪一行**。
**1. Cache 结构与寻址（大题核心）**
*   **地址划分**：物理地址 = **Tag (标记位) | Index (索引位) | Offset (块内偏移)**
    *   **Offset**：由 Block Size 决定（$2^n$ bytes $\rightarrow$ $n$ bits）。
    *   **Index**：由 Set 数量决定（$2^m$ sets $\rightarrow$ $m$ bits）。
    *   **Tag**：剩余的高位地址。
*   **映射方式**：
    *   **直接映射 (Direct Mapped)**：一个内存块只能映射到Cache中的一个特定位置。冲突多。
    *   **组相联 (Set Associative)**：内存块映射到某个固定组（Set），组内可以放在任意位置（Way）。
    *   **全相联 (Fully Associative)**：内存块可以放在Cache的任意位置（通常用于TLB）。

**2. Cache 参数的影响（曲线题/选择题）**
*   **Capacity (容量)**：容量越大 $\rightarrow$ 命中率越高（利用时间局部性），但访问延迟（Hit Latency）增加。
* ![[Pasted image 20251231175410.png]]
*   **Block Size (块大小)**：**【注意正反影响】**
    *   **正面**：增大块大小利用空间局部性，**减少强制未命中（Compulsory Miss）**。
    *   **反面**：块太大导致Cache中总块数减少，增加了**冲突未命中（Conflict Miss）**；且块太大会导致无用数据被预取（污染），反而可能**增加Miss Rate**。
* ![[Pasted image 20251231175941.png]]
*   **Associativity (关联度)**：关联度越高 $\rightarrow$ 冲突失效越少，但硬件更复杂，访问时间变长。
* ![[Pasted image 20251231175749.png]]

**3. 替换策略**
*   **FIFO**：先进先出。维护一个循环队列或计数器，替换掉**最早进入**该组的块。
*   **LRU**：最近最少使用（Least Recently Used），替换掉**最长时间未被 CPU 访问**的块，利用时间局部性，性能通常最好。

**4. 写策略（Write Policy）**
1. 写命中时策略
	*   **写穿透 (Write-through)**：更新Cache数据时同时把数据写入内存。
	    *   优：数据一致性高，内存始终是最新的。
	    *   缺：**速度慢**：因为每次写操作都要访问速度较慢的主存，性能受限于主存带宽。
	    *   配合：Write-no-allocate（写不分配）。
	*   **写返回 (Write-back)**：只更新Cache的数据，且标记为**Dirty**，被替换时才写回内存。
	    *   优：**速度快**：因为不需要频繁访问主存，写操作基本以 Cache 的速度进行。
	    *   缺：需要Dirty位，控制复杂。
	    *   配合：Write-allocate（写分配）。
2. 写未命中时策略
	- **写分配**：先把要写的数据所在的块从主存**调入 Cache**，然后在 Cache 中进行修改。
	- **写不分配**：直接把数据写入主存，**不**将该块调入 Cache。

### 三、虚拟内存（概念为主）

**1. 基础概念**
*   **作用**：让每个进程认为自己拥有独立的、连续的大内存；提供隔离和保护；允许内存大于物理内存（Disk Swap）。
*   **转换**：**虚拟地址 (VA)** $\rightarrow$ **物理地址 (PA)**。以 **Page (页)** 为单位。
*   **VPN (虚页号)** $\rightarrow$ **PPN (实页号)**，**Offset (页内偏移)** 不变。

**2. 虚拟内存的好处**（和上面作用差不多）
- 
	**1. 程序隔离**
	
	- **进程隔离**：每个进程有独立的地址空间，互不干扰。
	- **权限控制**：页表项支持设置读/写/执行权限（如保护代码段不被修改）。
	**2. 高效的内存使用(Efficiency)**
	
	- **按需分页 (Demand Paging)**：程序无需一次性全部加载，用到才加载。允许运行**比物理内存大**的程序。
	- **内存共享**：不同进程的虚拟页可以映射到同一个物理页（如共享 C 库）。
	**3. 简化内存管理 (Simplification)**
	- **抽象**：给程序员提供一个**连续、线性**的内存假象，无需关心物理内存的碎片和分布。

**3. 页表 (Page Table)**
*   **结构**：操作系统维护的数据结构，存储 VPN 到 PPN 的映射关系以及权限位（Valid, Dirty, R/W）。
*   **大小**：取决于页表项大小和虚页数量。
	* `页表大小 = 虚拟页数量 × 每个页表项(PTE)的大小`
    *   **大页 (Large Pages) 的优缺点** ：
        *   **优点**：
            *   **减少页表空间**：页变大，页的数量就变少，PTE 数量也变少。
            *   **减少页表层数/查找更快**：VPN 位数减少，可能让多级页表的层数也减少。
        *   **缺点**：
            *   **页内空间浪费（内部碎片）更严重**：`[S49]` 比如程序只需要 5KB 空间，但系统必须分配一个 2MB 的大页给它，造成了巨大的浪费。
            *   实现更复杂。


**4. TLB (Translation Lookaside Buffer)**
*   **是什么**：页表的 Cache（缓存近期使用的地址转换结果）。
*   **访问流程**：CPU先查TLB $\rightarrow$ Hit (直接得PA) / Miss (查页表，然后填入TLB)。
*   **TLB Miss处理**：
    *   **硬件处理 (x86)**：硬件自动遍历页表（快，但页表格式固定）
	    *   流程：MMU 硬件中有一个专门的 **Page Table Walker (页表遍历单元)**。一旦 TLB Miss，硬件自动暂停流水线，直接去内存读取页表，填入 TLB，然后重试指令。
	    *   **优点：** **非常快！** **开销**较小。**不触发操作系统异常**，不涉及特权级切换。
        *   **缺点：** 操作系统必须使用硬件规定的页表格式（如多级页表）。
    *   **软件处理 (MIPS)**：触发异常，OS处理（慢，但灵活）。
        *   **流程**：TLB Miss 会触发一个 **异常 (Exception)**。CPU 陷入内核态，跳转到操作系统的 TLB Miss Handler。OS 软件通过指令读取页表，计算物理地址，用指令 (`TLBWR`) 写入 TLB，然后从异常返回 (ERET)。
        *   **优点：** OS 可以自由设计页表结构（如哈希页表、反向页表）。
        *   **开销**：较大。涉及流水线冲刷 (Pipeline Flush) 和上下文切换。

**4. 缺页异常 (Page Fault)**
**1. 定义** 
当 CPU 访问的虚拟页面**不在物理内存中**时（即查页表发现 **有效位 Valid Bit = 0**），硬件触发的异常。

**2. 两种情况 (分类)**
- **非法访问 (Segmentation Fault)**：
    - 访问了未分配的地址或权限不够（如写只读区）。
    - **结果**：OS 终止进程（Crash）。
- **真缺页 (True Page Fault)**：
    - 地址合法，但数据在**磁盘**（Swap区）中。
    - **结果**：OS 负责将页面从磁盘调入内存。

### 四、乱序执行（Tomasulo算法）

**1. 基本思想**
*   **动态调度**：硬件在运行时调整指令执行顺序，为了掩盖长延迟（如Load/浮点运算）。
**2. 乱序执行要求哪些硬件结构？**
1. **保留站 (Reservation Stations)**：位于执行单元前，用于缓存等待操作数的指令，实现寄存器重命名以消除假相关（WAW/WAR）。
2. **公共数据总线 (CDB)**：用于广播执行结果，让所有等待该数据的保留站能直接获取数据（解决RAW）。
3. **扩展的寄存器堆**：每个寄存器增加Tag字段，用于记录数据来源（是来自哪个保留站）。
4. **重排序缓冲区 (ROB)**：用于强制指令按程序顺序提交，以支持**精确异常**处理（这是实现现代乱序执行的关键补充结构）。
**3. 核心组件与作用**
*   **保留站 (Reservation Station, RS)**：
    *   **作用**：缓存已译码但操作数未准备好的指令；监听公共数据总线（CDB）以获取操作数。
*   **寄存器重命名 (Register Renaming)**：
    *   **作用**：通过将指令的目标寄存器“重命名”为将要产生该结果的**保留站的 ID (tag)**，从而彻底消除了 WAR 和 WAW 这种因为寄存器名不够用而产生的伪相关，只保留了真正的 RAW 数据依赖。
*   **Reorder Buffer (ROB)（PPT未详述，老师要求补充）**：
    *   **作用**：确保指令**按程序顺序提交（Commit/Retire）**。
    *   **与保留站的区别**：RS 负责**乱序执行**（解决数据流），ROB 负责**顺序提交**（解决控制流和异常）。
*   **精确异常 (Precise Exception)（老师要求补充）**：
    *   **定义**：发生异常时，异常指令之前的指令全部完成，之后的指令全部未提交。ROB 保证了这一点，只有指令到达 ROB 头部且无异常时才写入寄存器/内存。

### 五、分支预测（大题预警）

**1. 饱和计数器 (Saturating Counter)**
*   **2-bit 状态机**：
    *   **状态**：Strongly Taken (11), Weakly Taken (10), Weakly Not Taken (01), Strongly Not Taken (00)。
    *   **规则**：预测错误时向反方向移动一步，预测正确向同方向饱和。
    *   **特点**：具有**滞后性**（Hysteresis），不会因为单次异常跳转就改变预测倾向（如循环退出时）。
    *   **做题注意**：看清题目给的初始状态和具体的跳转序列。

### 七、多线程（概念与优缺点）

**1. 细粒度 (Fine-Grained)**
*   **工作方式**：每个时钟周期轮转切换线程（Round-robin）。
*   **优**：能极好地**掩盖短时间和长时间的流水线停顿**。由于线程切换频繁，一个线程的停顿完全不影响其他线程的执行。
*   **缺**：**单个线程的执行时间变长了**。一个本来可以连续执行的线程，现在被其他线程的指令“插队”，导致其完成时间被拖慢。

**2. 粗粒度 (Coarse-Grained)**
*   **工作方式**：只有遇到**长延迟事件**（如L2 Cache Miss）才切换线程。
*   **优**：单个线程在没有停顿时可以独占流水线，执行速度快，不会被拖慢。
*   **缺**：
	*   无法掩盖短时间的停顿。
	*   线程切换时有较大的性能开销，因为需要**冲刷 (Flush)** 流水线。
	*   可能存在公平性问题，一个不怎么停顿的线程会“霸占”处理器。

### 八、Cache 一致性（大题/重点）

**1. 概念**
*   **Cache Coherence**：关注**同一个数据**在不同核心Cache中的副本是否一致。


**2. MSI 协议（【必考】状态转换表）**
*   **状态含义**：
    *   **M (Modified)**：独占且被修改（Dirty）。数据与内存不一致。本地读写不通知总线。
    *   **S (Shared)**：共享且只读（Clean）。数据与内存一致。
    *   **I (Invalid)**：无效。
*   **关键动作（看懂表格）**：
    *   **BusRd (总线读)**：别人想读。如果我是M，我要把数据写回内存（Flush）并变S。
    *   **BusRdX (总线读并独占/写)**：别人想写。如果我是S或M，我必须作废本地副本（变I）。
    *   **状态推导**：例如，本地是S，我要写 $\rightarrow$ 发送BusRdX $\rightarrow$ 变为M。
![[Pasted image 20260113101608.png]]
**3. MESI 协议**
*   **改进点**：增加了 **E (Exclusive)** 状态。
*   **原因**：MSI中，如果是单核读取了数据（S状态），写数据时仍需广播BusRdX，浪费带宽。MESI引入E状态（独占且Clean），写E状态不需要广播，直接静默升级为M。

### 九、多处理器内存一致性
*   **Memory Consistency**：关注**不同数据**在多个核心间的读写顺序。
	- 我们刚学过的 **Cache 一致性 (Coherence)** 保证了“对于**同一个**内存地址 A，所有处理器看到的值都是一致的”。但这还不够。**内存一致性 (Consistency)** 要解决一个更微妙的问题：“当处理器 P1 修改了地址 A，然后又修改了地址 B，那么其他处理器 P2 是先看到 A 的变化，还是先看到 B 的变化，还是看到的顺序不一定？” 这个**顺序**问题至关重要。

**1. 顺序一致性 (Sequential Consistency, SC)**

*   **概念**：所有处理器的操作看起来像是按某种全局顺序串行执行的，且每个内部保持程序顺序。
*   **优点** ：
    *   **简单、直观**：完全符合程序员的编程直觉，非常容易理解和推理。

*   **缺点** ：
    *   **性能极差**：为了实现这种严格的全局顺序，硬件上几乎**禁止了所有高级的性能优化**。比如，写缓冲、乱序执行、指令重排等技术，因为它们都可能破坏 SC 要求的严格顺序。
    *   **不必要的限制**： 很多时候程序并不需要这么强的顺序保证，SC 的限制过于严苛。

### 十、GPU（【重点】大题）

**1. 设计思路（对比CPU）**
*   **简化流水线**：去掉乱序、预测等复杂逻辑，节省面积。
*   **增加核数**：利用节省的面积堆ALU，提升并行吞吐。
*   **SIMT**：单指令多线程。多核共用取指/译码单元。
*   **海量线程掩盖延迟**：不使用Cache掩盖延迟，而是通过快速切换大量线程来掩盖内存访问延迟。

**2. 线程调度（大题）**
*   **层级**：Grid $\rightarrow$ Block $\rightarrow$ Warp $\rightarrow$ Thread。
*   **Warp**：硬件调度的最小单位（通常32个线程）。
*   **调度器**：Block分配给SM（Streaming Multiprocessor），SM内部按Warp调度执行。

**3. 分支分歧 (Branch Divergence)**
*   **问题**：SIMT架构下，如果Warp内线程走到if-else不同路径，无法同时执行不同指令。
*   **解决机制（掩码+栈）**：
    1.  所有线程先走 `if` 分支，不满足条件的线程(else分支的)被**掩码**（Mask）禁用（空转）。
    2.  然后所有线程走 `else` 分支，刚才执行过的线程被掩码禁用（反转掩码）。
    3.  最后汇合，所有线程重新激活，继续执行后面的公共代码。。
*   **关键点**：串行执行了两个分支，性能下降。
